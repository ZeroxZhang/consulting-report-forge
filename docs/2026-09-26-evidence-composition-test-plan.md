## B. 逐图渲染与比较

| 编号 | 输入/动作 | 必须结果 |
|---|---|---|
| B01 | 两张同型图，容量不同；第二张超限 | 定位第二张图；不套用第一张容量 |
| B02 | 主图与次图异形，次图缺 data-form/capacity | 新策略下拒绝所需标记缺失；不能只检查 page.form |
| B03 | 移除、重复、交换 panel 根身份，或多加未登记实质展品 | 检出身份/清单不一致；不借邻图标记通过 |
| B04 | 屏幕正常、打印隐藏第二张图 | HTML 与 PDF 对照阻断交付 |
| B05 | 两个 panel 各有合法瀑布 | 新策略接受，各自对账；旧策略保持原拒绝 |
| B06 | 仅篡改第二张瀑布输入、零轴、残差或模型标记 | 逐图核对失败，不以另一张正确结果覆盖 |
| B07 | 一个 panel 内重复对账轴 | 仍然拒绝 |
| B08 | 声明共同量尺但可验证的 domain/unit/scaleType 不同 | 自动拒绝或按明确规则要求纠正，不视为正常同尺 |
| B09 | 有用途的独立量尺并显著说明 | 合法；不得误判所有异形组合必须同尺 |
| B10 | 自绘 SVG 无真实尺度元数据 | 记录自动未覆盖项并要求实际审查，不能伪称已自动验证 |
| B11 | 多图字号/图例过小、来源侵入、裁切与错位 | 按现有可读性/几何规则处理；逐页实际查看 HTML/PDF |
| B12 | 相同 domain 但绘图区不同，却声明可直接比较长度/斜率 | 对受支持渲染器核像素映射；不把相同上下界当成充分条件 |
| B13 | 多 panel 共用一个页脚来源；调换其中一个引用或说明归属 | 合法共享通过；错误归属被定位，不要求重复完整来源 |

## C. 版本与审查生命周期（发布阻断项）

| 编号 | 输入/动作 | 必须结果 |
|---|---|---|
| C01 | pages1/2/3、blueprint2/task1、blueprint3/task2 旧夹具 | 接受/拒绝结果和既有摘要保持 |
| C02 | task3 省略策略；task3 显式旧策略 | 不自动启用组合及新的默认规则 |
| C03 | 新策略任务交给冻结的 1.5.0 读取器 | 因未知策略明确拒绝 |
| C04 | 旧策略加组合 marker，或 pages/HTML/audit 策略不一致 | 新运行时拒绝；直接底层脚本也不能正式放行 |
| C05 | 新组合策略分别搭配 single-page/reference-block | 组合、细线及来源检查均生效，不互相覆盖 |
| C06 | 对旧蓝图仅切策略、保留旧 analysis-review2 | 拒绝缺新策略身份/覆盖的签署，草稿 incomplete |
| C07 | 改 panel 数据、关系、编码、量尺、主张或来源 | 分析摘要/适用审查失效；可定位变化 |
| C08 | 只改 CSS 间距 | 保持原分析投影逻辑，视觉页仍重审；不得过度承诺所有布局变化都免分析审查 |
| C09 | 第一次启用新策略 | 按公共依赖使整册视觉复用失效 |
| C10 | 同策略验收快照后仅改一页 | 原未变页按现有规则可继承，变化页需两媒介复看；全局审查待完成 |
| C11 | 页序、panel 映射、公共字体或脚本改变 | 按页身份/语义/公共依赖失效，不错误继承 |
| C12 | 迁移中断、目标已存在、附件路径不便携 | 原件哈希不变；失败有清晰状态且清理临时文件，不生成 PASS |
| C13 | 旧、新快照迁移目录后验证和打包 | 原引用链自足且可验证，篡改仍拒绝 |
| C14 | 退回新建默认策略 | 已创建的新策略任务仍由支持它的运行时处理，不删标记伪降级 |
| C15 | 两个同型 panel 出现相同 code 告警，分别存在 screen/print | 只按同图同对象归并媒介；一图的处置不能覆盖另一图，旧 warningReview 身份不变 |
| C16 | 自绘尺度等人工补查项仅列入 findings，或删除其处置记录 | aggregate/package 拒绝缺失处置；panel/relation/scaleGroup 与媒介各有明确覆盖，不能由页级已看过代替 |

## D. 技能行为与成品验收

代表页覆盖上下三层、三栏互补、矩阵分面、总览加细节、趋势/机制/表格互补、双瀑布、定性组合、合理单图。每种保存可复现输入、蓝图、构建方式、HTML/PDF 和真实审查记录，不只保存漂亮截图。

旧版与候选使用相同的 6 个任务、模型、材料、页数范围和资源约束，各任务各版本至少 2 次。制作者处于干净上下文，不提示预期版式。审稿者看隐藏版本标签的全册联系表和原页，分别判断：

- 页结论是否由证据支持，是否出现为凑图新增的事实或推断。
- 多图各自增加了什么，组合关系能否直接读出。
- 分栏、上下或嵌套是否符合信息量和比较任务。
- 单图、连续同型及定性任务是否被不必要复杂化。
- 两种媒介是否完整、可读、口径与来源清楚。
- 记录实际运行/返工次数与耗时；工程覆盖及创作效果分别报告。

成品有重大分析或阅读问题时不以平均分抵消。小样本只能证明覆盖这些案例，不声称普遍提速或整体模型能力提升。

## E. 执行与结果记录

实施后执行既有 `npm test`、`npm run test:render`、`npm run test:upgrade-render`，以及涉及严格合同和参考资料的 `npm run test:upgrade-r2`、`npm run test:upgrade-r3`；新测试脚本在 P2/P3 接入相应套件。失败修复后运行相称的受影响测试，发布候选执行完整必要回归。

对关键旧算法和新策略拒绝行为使用冻结夹具，不用待测新版 helper 同时生成“期望结果”。旧摘要应按原合同逐字相等；像素和 PDF 字节比较须固定环境，跨环境变化不能误判为摘要兼容性破坏，但仍需媒介检查。

性能测量覆盖 1/3/6/9 图页及 16:9、4:3，记录编译、浏览器探针、PDF、内存与失败情况。测量计划不增加产品图数上限。升级前后相同环境比较，不预填百分比目标。

每次验证记录实际命令、运行时/模型身份、输入哈希、产物路径、审查实例、通过/失败、未覆盖范围及返工原因。最终升级完成记录只能引用真实执行结果。
