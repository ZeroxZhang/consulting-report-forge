# 咨询报告页面构思与复合证据升级方案

日期：2026-09-26。基线：运行时 1.5.0，Git `95e3935`。状态：供实施使用的设计提案；本文不代表功能已经实现、测试已经通过或产品已经发布。

## 1. 建议与完成标准

建议将下一轮升级定位为“按论证组织整页证据”，候选版本为 **1.6.0**。目标是让单图、上下、三栏、矩阵、总览加细节、图表与机制组合都能依据内容自然产生，并让同页多图获得与单图同等可靠的制作、校验和审查能力。

推荐复用现有 38 个目录布局、custom 路线、指标与来源真源、静态 HTML/PDF 工具链。新增一套轻量的复合证据合同及其适配模块，不重建排版引擎，不引入第二套数据或来源系统。

完成必须同时满足：

1. 新制作流程先明确页结论、证据分工和图间关系，再确定图形与空间组织；单图仍是有效结果。
2. 代表样例能稳定呈现上下、三栏、嵌套、同形分面和异形互补，多图之间有可解释的共同任务。
3. 每个图表或文字展品都有稳定身份，可逐项核对实际形式、数据绑定、容量、来源与打印存在性。
4. 旧任务、原算法摘要、旧审查、旧快照及旧渲染路径保留原解释；新功能不能悄然回退为单图检查。
5. 通过合同测试、真实 HTML/PDF 验证，以及同题、同模型、同材料条件下的技能行为评估。工程通过不能替代创作质量评估。

## 3. 设计原则与方案取舍

**一个页面围绕一个核心判断，证明它可以需要一个或多个展品。** 图、表、机制、证据摘录、注释均可承担证明职责；阅读入口不代表该图必须占最大面积。

| 路线 | 收益 | 成本与问题 | 选择 |
|---|---|---|---|
| 只改提示词、补版式图片 | 改动少，适合作为原型验证 | 不能解决逐图身份、容量、瀑布及审查覆盖缺口 | 作为早期验证，不作为完整交付 |
| 现有展品语义内新增组合合同，显式策略启用 | 保留现有真源和版本链，补齐多图制作能力 | 需接通编译、探针、审查与复用 | 推荐 |
| 同时新建 blueprint4/task4/pages5 与语义算法 | 可以重新设计全部接口 | 迁移面大；当前尚无必须改算法或重建格式的证据 | 本轮不采用 |

不规定每份报告必须使用多少种布局、不限制 L01 的使用比例、不强制每页至少两张图、不用随机模板轮换制造变化。布局复杂度必须由关系与阅读任务支撑。

## 4. 制作流程的升级

### 4.1 在标题链之后，先组织证据

每页用紧凑记录回答：本页证明什么；哪些证据共同支持它；各展品分别让读者看出什么；展品之间是对照、拆解、递进、互补、总览与细节，还是边界与反证。

只有证明任务有变化，才增加展品或区域。不为结构字段编造新数据；缺失证据沿现有 gaps 机制处理。editorial 保留原意，不因新版布局要求擅自增加结论。

### 4.2 从关系选择页面结构

| 阅读任务 | 可用组织方式 | 应核对的关系 |
|---|---|---|
| 同对象不同期间/方案 | 等宽双栏、上下对照 | 同口径、共同量尺或明确不可直接比大小 |
| 一个判断的多项互补证据 | 三栏、上总下分、非对称组合 | 各图有不同贡献，且共同支持页结论 |
| 整体情况与关键局部 | 上总览下细节、主区内嵌局部、左右嵌套 | 局部来自哪里，放大或筛选规则是什么 |
| 分解或递进 | 上中下、左中右、桥接与结构表 | 先后关系、算术关系与因果关系不能混淆 |
| 多对象同口径比较 | 小多图、矩阵、图表配精确表格 | 对象顺序、图例和比较尺度一致 |
| 定性发现及边界 | 证据摘录、机制、条件表组合 | 不把访谈频次包装成市场规模 |
| 单个强证据 | 全幅单图、图内注释、L01 | 支持证据确有用途，单图没有遗漏必要关系 |

不建立“问题类型只能对应某个模板”的路由白名单。作者按内容使用目录或 custom；图谱提供空间约束与参考，不能代替构思。

### 4.3 代表页与整册复核

仍采用先代表页后批量生产的流程。代表页按风险挑选：同页多图或最复杂关系、最密内容、定性页；全篇确实只有单图任务时不强凑复合页。

代表页先比较真实绘图区与完整阅读路径，成熟后再扩展。整册缩略图审查具体记录：哪些重复服务比较，哪些只是沿用外壳；哪些相邻页更适合合并，哪些组合应拆页。理由要指向实际证据，不以布局种数替代判断。

## 5. 数据与渲染架构

### 5.1 一条权威数据链

```text
claims / metrics / sources / artifacts（现有真源）
                       │ 引用、计算、已采纳依赖
                       ▼
slide.proves + exhibit.semantics.composition
  ├─ panels：每个展品的任务、形式、数据引用、容量、编码
  ├─ relations：展品如何共同支持页结论
  └─ scaleGroups：有跨图比较时的量尺约定
                       │ 新策略验证 + 兼容投影
                       ▼
pages4：已解析的组合 + 派生的 page.form / regions
                       │ 现有装配器、图表渲染器与 HTML/CSS
                       ▼
带稳定 panel 标识的 HTML → 逐图探针 → HTML/PDF QA
                       │
前置分析审查 + 最终页级双媒介审查 → 快照 / 复用 / 交付
```

建议新增 `scripts/composition_contract.cjs`，集中完成结构校验、依赖提取、兼容投影、期望图示清单和实测对账规则。策略能力表扩展在现有 `contract_capabilities.cjs`，组合模块消费其结果，不另建策略白名单。现有入口调用共享模块；不在蓝图、QA、审查各维护一份组合规则。浏览器侧只采事实，合同判定尽量保留在可测试的纯函数中，避免 normalizer 与组合编译器互相调用形成循环依赖。

### 5.2 最小结构

组合放入现有 `semantic-exhibit-v1` 的 `semantics.composition`。以下是拟议结构片段，不是当前可直接运行的完整蓝图：

```json
{
  "exhibit": {
    "contract": "semantic-exhibit-v1",
    "semantics": {
      "composition": {
        "version": 1,
        "anchorPanel": "revenue",
        "readingOrder": ["revenue", "cost", "profit"],
        "panels": {
          "revenue": {
            "purpose": "比较同期间收入变化，建立利润诊断的背景",
            "claimRefs": ["revenue-change"],
            "form": "kit.dumbbell",
            "selection": {
              "relationship": "comparison",
              "reason": "以同一量尺标出两个期间的收入水平与差额。"
            },
            "capacity": {"items": 1},
            "data": {
              "before": {"$metric": "revenue-before"},
              "after": {"$metric": "revenue-after"}
            }
          }
        },
        "relations": [
          {
            "id": "revenue-cost-profit",
            "kind": "complement",
            "panelRefs": ["revenue", "cost", "profit"],
            "reason": "收入、成本及利润变化共同解释会计算术关系，不据此识别经营因果。"
          }
        ]
      }
    }
  },
  "visual": {
    "layout": "custom",
    "regions": [
      {"slot": "left", "role": "primary", "span": 1, "panelRef": "revenue"},
      {"slot": "main", "role": "evidence", "span": 1, "panelRef": "cost"},
      {"slot": "right", "role": "evidence", "span": 1, "panelRef": "profit"}
    ]
  }
}
```

上例省略 cost/profit 的展品定义与全局主张、指标、密度，完整样例须全部补齐并可编译。字段名称在 P0 合同设计时冻结；不能直接照此片段生成正式交付。

具体边界：

- `panels` 用稳定键；改变 DOM 顺序不能改变展品身份。主张仍只在全局 claims，数值仍只在 metrics 或已验附件。
- `panel.claimRefs` 表示本展品承担的页内证明分工，应是 `slide.claimRefs` 的子集。统一依赖解析器仍显式检查并纳入这些引用，拒绝不存在、未采纳或未完成的依赖；不能只核对字符串存在。
- `$metric` 及现有 displayBindings/exhibitBindings 继续使用；组合中的数据继续处于 `/exhibit/` 下。编译后保留所需主张、指标与派生来源，不另写来源正文。
- 每个 panel 的 form、selection、capacity、数据、瀑布输入只有一份权威声明。新策略下 `visual.regions` 只声明位置与 panelRef；编译适配层派生旧格式必需的 region.form、page.form、primary、selection、capacity。作者若同时写重复字段，必须一致，否则报冲突，不能择一覆盖。
- anchorPanel 只表示阅读入口；旧 page.form/primary/selection/capacity 始终从布局唯一 primary 区域所绑定的 panel 派生。二者允许不同，不能把阅读入口强塞进目录的主槽位；也不要求阅读入口更大。目录既有 primary/slot 仍由目录定义，不能修改旧 L01–L38 的含义；新结构选用可承载目录或 custom。
- 初版每个阅读区域绑定一个 panel，每个 panel 对应一个审计根；不引入任意递归的布局树。嵌套几何由 custom CSS 组织，叶展品仍逐个登记；共用的纯几何 wrapper 不标 data-panel-id/data-module、不另消耗一个声明区域。panel 审计根互不嵌套，内容由最近的 panel 根唯一拥有，父节点不能借后代图表凑形式或容量。组件内部轴、标签、sparkline 等属于其 panel，不自动变成新 panel。
- 单图页面使用一个 panel，relations 可以为空；多 panel 页面须解释它们的组合关系。关系类型提供常用项及带解释的 other，不把登记表变成表达白名单。
- 保留现有 density 三档和证据职责簇。一个职责簇可由多图共同承担，同一图也可含基准或限制；不按图数计算密度，不为维持字段增加空话。

### 5.3 几何与语义分开

图间比较关系、单位、期间、分母、尺度类型、定义域、颜色所表达的意义进入 semantics。实际位置、间距和尺寸沿现有 CSS、layout、regions 及受限 style 表达。数据不得藏在 style 中。

复用 `semantic-v2` 的既有投影，不扩大排除字段。已有投影会纳入区域的部分语义及数组顺序，不能承诺所有区域重排都不触发分析重审。单纯 CSS 间距变化可不改分析摘要，但视觉仍须复核；关系、编码或区域分工变化保守重审。

### 5.4 渲染接入

所有已登记的形式继续用原有渲染器，输入改为对应的已编译 panel。新增的是薄适配层，不重写 ECharts、SVG、表格和机制图实现。

建议在 panel 根节点使用 `data-panel-id`，所属页用现有 `data-page-id`；两者组成稳定身份。现有探针生成的 `data-deck-exhibit-id` 保留为媒介查找辅助，不能充当业务 ID。一个 panel 下意外出现多个不属于登记形式内部结构的顶层展品，须拆分登记或明确组合语义，不能悄悄漏检。

HTML 文字、表格、KPI、finding 和自绘 SVG 都纳入 panel 清单。装配阶段既检查漏项，也检查额外未登记的实质展品；装饰元素、图内注释和来源节点按明确规则排除。

共享来源可以只在页脚出现一次，各 panel 使用可识别的引用编号指向它。核对 panel—编号—页脚来源的对应，不为绑定重复塞入完整来源段落。关键指标、限制和主张的现有 content-key 绑定同时记录所属 panel，防止把 A 图的说明写在 B 图下却因全页出现过就通过。

## 6. 校验与审查升级

### 6.1 逐 panel 校验

| 项目 | 自动检查 | 需要实际读图的部分 |
|---|---|---|
| 身份与覆盖 | ID 唯一、引用存在、区域映射完整、屏幕与打印均存在 | 阅读顺序是否自然 |
| 形式与容量 | 每个 panel 独立执行既有 form/capacity；同形图各用各的计划 | 数据标签、图例和文字是否实际可读 |
| 数据与来源 | 指标、附件绑定、身份、主张及来源闭包；不得跨 panel 借用一个标记蒙混通过 | 数据含义及主张是否成立 |
| 共用量尺 | 对输出可核对尺度元数据的渲染器，比较 domain、unit、scaleType 等 | 任意自绘 SVG 的真实几何、独立量尺是否造成误读 |
| 瀑布 | 每张瀑布自己的权威输入、零轴、起终点、贡献与残差分别核对 | 归组是否合理、算术桥是否被说成因果 |
| HTML/PDF 一致 | 每个 panel 及关键标签均在两个媒介出现；打印隐藏、裁切等进入现有检查 | 整页层级和跨图关系是否在 PDF 中仍成立 |

量尺检查不能仅比较作者手写的两个“共同量尺”标签。相同 domain 不保证相同视觉比例：若阅读任务要求直接比较图形长度、高度或斜率，还要核对绘图区尺寸与数据到像素的映射；不同尺寸且只要求逐轴查值的图，需明确比较边界。新策略要求声明支持自动核查还是仅人工覆盖；没有可核对元数据的自绘图明确记为人工项，不宣称完成全自动数值几何验证。

新策略下将瀑布体检作用域从页面下沉到 panel，允许同页两张独立瀑布；一个 panel 内出现重复对账结论仍阻断。旧任务保持原 WF-MULTIPLE-AUDIT 规则，不能全局删除原检查。

### 6.2 三类结果分开

- **硬错误**：错引用、漏图、多图错绑、容量越界、数据不一致、对账失败、比较尺度声明与可验证实测冲突、关键内容不可读或打印缺失。
- **审稿诊断**：连续相同结构、图间贡献可能重复、大片无用途空白、侧栏复述、相邻页合并机会；必须结合画面处置，不以数量直接判失败。
- **能力未覆盖**：任意 SVG 几何、复杂裁切等自动探针未覆盖部分；说明人工检查对象，不能把未测量写成通过。

新策略诊断携带稳定的 pageId/panelId/code/subject 与媒介身份。跨媒介归并只合并同一 panel 的同一问题，不能把同页两张同型图的错误合成一个后共享处置。同步核对 diagnostic_summary、review_pack 及 warningReview 的匹配路径；旧告警字符串和历史处置身份保持原样。

### 6.3 审查身份与覆盖

analysis-review2 在新策略下条件增加策略身份及组合覆盖记录，例如按 slideId 登记 panelRefs/relationRefs。清单由合同派生，审查者填写实际所见，工具不生成 PASS；按现有必需角色合并覆盖，不能用作者身份填独立审查。

原因是 task.policyVersions 不进入现有 analysisSha256。仅切换视觉策略而不改蓝图时，旧前置审查摘要可能仍匹配。新策略必须明确拒绝没有对应策略身份与覆盖的旧签署，生成 incomplete 草稿后实际重审。

final-review5 保留页级双媒介覆盖，在新策略下加入组合关系、密度和结构取舍的可审记录。页面内部多图检查由 audit 与组合审查清单连接，不能只签“看到该页”。editorial 的前置豁免保持，最终组合审查不豁免。

自动检查未覆盖而需要人工补查的项目，必须从 audit 派生稳定身份，包含 page、panel/relation/scaleGroup 与媒介，并接入现有 warnings/处置验证链。只放进 visualPolicy.findings 供展示不算完成闭环。最终审查逐项提供观察依据；缺少任何必需处置时 aggregate/package 拒绝。草稿可预填对象和待查原因，不能预填“已核实”。

## 7. 版本、兼容与迁移

### 7.1 推荐合同路径

保持 blueprint3 / task3 / pages4 / semantic-v2 / analysis-review2 / final-review5 / snapshot1。新增显式视觉策略 `evidence-composition-1`，通过现有四项 policyVersions 中的 visual 启用；不添加第五项，不改已有缺省策略。

该策略的能力定义必须包含当前 structural-lines-1 的检查与新增逐 panel 检查。用集中式能力查询替代散落的字符串相等判断，避免换策略值后细线检查意外失效。

| 输入/任务 | 升级后处理 | 禁止行为 |
|---|---|---|
| pages1/2/3、blueprint1 历史路径 | 原校验、原格式读取 | 套用新角色、密度或图数规则 |
| blueprint2/task1/pages4/final-review3 | 原内容绑定合同 | 自动补组合或分析签署 |
| blueprint3/task2/pages4/analysis-review1/final-review4 | 原 legacy-v1 分析链 | 悄悄切 semantic-v2 |
| task3 省略 policyVersions | 保留原 legacy-1/single-page-1 等缺省解释 | 因升级运行时而启用新策略 |
| task3 明确 legacy-1 或 structural-lines-1 | 原单页/多区域合同与原渲染检查 | 原地改旧摘要、改旧审查 |
| task3 + evidence-composition-1 | 新组合验证与审查，仍用原语义摘要算法 | 缺 panel 计划时退回“只查主图” |
| 旧策略输入新的组合标记 | 新运行时明确提示需要显式升级 | 只把未知内容纳入签名、忽略组合检查 |
| 1.5.0 读取带新策略的 task | 原 normalizer 因未知 visual 策略拒绝 | 宣称旧运行时可制作或验证新报告 |
| 旧完整快照 | 按其内部旧合同验证，保持自足迁移能力 | 批量改写 manifest、补字段或重签 |

新代码还须校验“组合 marker、task 策略、派生 pages、HTML 内嵌合同、audit”一致。直接运行底层 compile/ready/preview 也不能绕过策略检查；preview 可未签，但不能伪装旧合同获得正式交付。

上述正向拒绝保证针对保留真实合同的正式工具链；不声称能阻止用户手工删改合同后运行任意历史脚本。打包与正式 QA 必须回读权威蓝图及任务绑定。

只有出现以下实际需求才另提版本升级：改变既有语义投影规则、改变旧合法记录的解释、或无法用新策略清楚判定审查格式。不得为了维持版本号而放宽验证；也不预先制造没有必要的新主版本。

### 7.2 迁移规则

不批量迁移旧报告。显式升级时复用现有“新目录、锁、原字节归档、失败清理”的迁移机制，扩展出组合迁移入口或模式；命令名在实施时确定。

迁移可以复制原数据和记录、建立现有区域的候选 panel 映射；不能猜测图间因果、自动分配未验证主张、复制旧 PASS，或把一张自绘总图假装已拆成可审的多个图。无法确定的内容进入 pending，草稿固定 incomplete。

任务新策略进入现有视觉公共依赖，因此首次启用会使**整册视觉复用失效**。重新生成 acceptance，并完成所需角色的整册 HTML/PDF 审查；这是一项明确的一次性兼容成本。之后同策略内按现有规则复用未变化页，最小复用粒度仍是页，不是图。

冻结并验证 legacy-v1、semantic-v2 的旧输入摘要。旧 review、audit、截图与快照的原字节不改写；新迁移副本重新计算当前合同的绑定，不回填原记录。

### 7.3 上线与回退

候选阶段仅显式启用新策略，`report init` 的默认入口保持 1.5.0 行为。所有验收完成后，1.6.0 的新任务模板切换新策略，研究阶段仍可没有页面；新规则到页面规划/ready 时才要求完整 panel 声明。

已有任务无论何时打开都不被改写。回退首先撤回“新建任务默认启用”，并为已创建的新策略任务保留支持该策略的运行时；不能把其 visual 改回旧值以消除报错。必要时从原基线创建独立旧合同任务重新制作与审查。

发布时同步 package.json/package-lock、SKILL、references、模板、README、维护文档、验证记录和技能桥接状态。沿现有唯一真源及 dbs-bridge 入口，不复制多套 skill，不将历史完成记录重写为当前规则。提交、推送与发布另按当次用户授权执行。

## 10. 测试与技能行为评估

详细执行矩阵见 [测试计划](2026-09-26-evidence-composition-test-plan.md)。确定性测试继续用现有 Node/assert 脚本；真实媒介验证继续使用现有浏览器和 PDF 路线。

```text
任务与组合标记
  ├─ 旧策略 + 旧内容 ── 原合同基线 [回归]
  ├─ 旧策略 + 新组合 ── 明确拒绝 [单元/集成]
  ├─ 新策略 + 缺失/错误计划 ── 定位到页/图的错误 [单元]
  └─ 新策略 + 有效组合
       ├─ 引用/依赖/语义摘要 [单元 + 变异]
       ├─ 兼容投影/编译/装配 [集成]
       ├─ HTML 与 PDF：各图数据/容量/存在性 [真实媒介]
       └─ 审查 → 快照 → 修订 → 复用 → 打包 [端到端]

技能提示与样例
  ├─ 已知需要复合证据的任务 [干净上下文评估]
  ├─ 单个强证据/合理连续同型 [反向正例]
  └─ 同题旧版与候选版 + 独立读图 [成稿质量评估]
```

工程样例至少覆盖：上下三层、三栏互补、四格同口径、总览加细节、趋势加机制加边界表、双瀑布、定性证据组合、合理单图。每种至少有一个会暴露错误的变体；样例种数是测试覆盖要求，不是用户报告配额。

技能行为评估建议选择 6 个任务：经营诊断、市场比较、方案敏感性、定性研究、已确认内容重排、单图/连续同型对照。每个任务对基线与候选各执行至少 2 次，记录模型、提示、材料、资源约束、起止时间、返工和产物；保持页数范围及输出要求一致。给制作者的任务不能直接要求目标版式或泄露期望答案。

评价分开报告：结论支持度、各展品贡献、跨图关系、空间适配、可读性、重复是否合理、HTML/PDF 一致、实际制作负担。盲化版本标签，保留完整联系表及逐页证据。允许候选在某题继续选 L01；如果仍机械套用单图加侧栏、或以堆图换复杂度，均不得宣称升级达成。

发布底线：全部兼容硬断言通过；代表页无未解决重大问题；需要复合关系的任务能被独立审稿者看懂且没有数据/边界退步；单图和定性对照不被强迫加图。若受控评估未能显示实际改善，保持候选状态并调整构思规则/示例，不能只凭测试全绿切默认。

## 11. 主要失败模式与性能约束

| 失败模式 | 处理及验证 |
|---|---|
| 新字段仅被签名，未进入依赖/检查 | 统一解析器验证 claim/metric/artifact 闭包；幽灵引用和 pending 依赖反例 |
| 两张同型图共用 page.capacity，漏掉第二张越界 | panel ID 定位各自计划，交换容量与越界反例 |
| 同页两条瀑布被当一条，或全局取消旧限制 | 新旧策略分别断言，独立篡改其中一图及重复轴反例 |
| 新视觉策略关闭既有细线检查 | 能力查询和策略组合回归；reference-block 等独立策略交叉测试 |
| 仅切策略后复用旧分析 PASS | 条件审查身份与覆盖不满足即拒绝，迁移只生成 incomplete |
| 跨图独立量尺看起来像同尺 | 实测支持范围明确；有意错 domain/unit 与人工读图用例 |
| 新图缺印刷版本，页面总数仍相同 | 按 panel 核屏幕/打印存在性并实际核 PDF |
| 改图间语义却继承旧审查 | 语义变异摘要测试、页计划指纹与当前全局审查 |
| 自动化评测只检查字段，模型继续机械套版 | 干净上下文同题对照，独立读实际成稿 |

性能按页内 panel 数和数据点数增长。每页一次 DOM 遍历收集全部 panel，建立 ID 索引，避免每图重新加载页面或导出整册 PDF；图间关系校验使用索引，不做全图两两笛卡尔遍历。指标池按一次编译计算复用，沿用现有字体和预览缓存。

记录 1/3/6/9 图页在两种画幅下的编译、预览和 QA 耗时与失败情况；这些数量用于压力覆盖，不成为图数上限。制作期只重预览受影响页，最终保持现有完整 acceptance。没有测量前不承诺固定耗时、性能提升或无限图数。

## 12. 本轮明确不做（NOT in scope）

- 自动布局优化器、任意递归排版语言：现有目录与 custom 足够，优先验证页面构思和逐图合同。
- 按图数、模板数或重复次数设质量配额：会鼓励形式变化而非证据质量。
- 重写所有图表库或增加大量新图型：本轮解决既有图形如何共同论证。
- 任意 SVG 的全自动数值几何证明：现有能力不足，保留精确映射和实际审查边界。
- panel 级审查继承：现有页级双媒介复用保持，避免局部通过掩盖整页关系变化。
- 自动重排、重签全部历史报告：旧报告稳定性优先，显式迁移才创建新副本。
- 同时新增 PPTX、更多画幅或交互式交付：保持现有两画幅、静态 HTML/PDF 范围。

这些边界直接记在本方案，不另造无上下文的待办列表。若未来目标变化，再以实际任务证明新增能力的必要性。
