# 1.8.0 模块填充检查：实施与验证

本次解决正文单页内部模块、尤其文字栏出现大量无功能留白，却被整页或父容器的“饱满”掩盖的问题。新增 `module-fill` 固定要求，接入排版前规划、代表页观察与最终 HTML/PDF 审查。

## 实施边界

- 新建任务与无计划 task3 的显式 adopt 使用 `execution-plan-2`；原 `execution-plan-1` 固定文本、任务定义及历史审查保持不变。没有原地迁移旧计划或补签历史检查。
- 规划必须逐正文页列区域内容、布局与留白安排；代表页须覆盖当前截图中所有已枚举模块/栏，并允许明确身份的补录。规划结构校验不能证明人工已枚举所有实际子模块。
- 探针在屏幕和打印媒体分别采集正文、模块和栏的真实文字行框及媒体边界，检测上下左右空带、空三分带与裁切风险。稀疏 SVG 按整体媒体处理；图形内部仍需实际审查。
- 最终审查逐区域、逐媒介绑定当前证据，另核对枚举完整性；每个预留区域有具体用途，每个诊断有明确处置，手动补录也须覆盖 HTML/PDF。
- 85% / 60% 仅用于有真实默认排版基线的诊断分流。成稿投影占用率不冒充默认字号填充率，不按单一数字签署美学通过。
- 真实裁切须修复重跑；D3 只能在实际证据确认是测量误报时记录误报依据，不能作为设计留白保留。

## 2026-10-09 验证结果

| 检查 | 结果与范围 |
|---|---|
| `npm test` | 通过全量现有合同与新增模块审查回归 |
| `npm run test:execution` | 通过旧工作流真实 HTML/PDF、打包、归档、恢复及复用链 |
| `npm run test:module-fill` | 通过新审查合同、真实 Chromium 定位和新工作流真实 HTML/PDF 生产链 |
| 新工作流拒绝路径 | 缺规划记录、缺代表页观察、遗漏最终区域、无身份补录均拒绝；审查包只生成未审草稿 |
| 浏览器针对样例 | 透明满高文字框、邻栏遮掩、脚注之间中空、横向空白、稀疏 SVG、预留区域、打印新增裁切与稳定区域身份 |
| 审查针对样例 | 缺媒介、缺诊断处置、D3 设计豁免、预留未逐个核实、伪填充率、父子结构错误、单媒介手录、借用他人证据均拒绝 |
| 独立代码复查 | 旧工作流三种工作模式的固定任务定义与旧版本逐字节一致；发现并修复代表页不能补录遗漏区域的问题 |
| Skill 与文档 | quick_validate、差异空白检查、相关文档链接检查通过；各 Agent 入口仍指向本项目真源 |

生产链的作者/独立审查内容是明确标记的合成测试数据，用于验证门禁和证据关联，不代表真实报告已经通过美学审查，也不证明报告质量提高的幅度。无候选不等于无缺陷，探针未识别区域、图形内部与设计功能仍由实际视觉审查负责。
