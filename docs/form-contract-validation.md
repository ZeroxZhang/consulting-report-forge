# 选型、图示语义与容量合同验证

本轮修复了上一轮审计记录的三个表达工具缺口。适用范围是 schema 3 蓝图与本包已登记的图示渲染器；历史 schema 2 蓝图和旧 pages 合同继续按原规则读取。

| 改动 | 机器能核对的事实 | 仍需人判断的事 |
|---|---|---|
| 选型 | `visual.selection.relationship/reason` 存在，关系允许用于所选 `form`；蓝图、派生页及最终任务计划一致 | 理由是否贴合真实问题，是否存在更清晰的图 |
| 图示语义 | 五种 `diagram.*` 的节点、边、循环、条件和交接规则；最终浏览器页面复核可见节点、连线、标题、线型、概率文字与形式声明 | 边所声称的作用、条件或概率是否有业务证据 |
| 容量 | `assets/form-capacity.js` 是形式专项容量数字真源；硬上限在蓝图计划与渲染输入拦截，建议阅读量只提示；最终 SVG 实际计数与蓝图计划对账；生成目录过期会失败 | 字体、标签、版位与读者负担的实际可读性，自绘形式的容量 |

覆盖的反例包括：缺失选型依据、关系与形式不符、哑铃图超行数、ECharts 分组系列超限、精度瀑布旧输入超限、机制循环未标反馈、流程手填线宽、泳道缺实际轨道、层级无包含关系、条件概率缺依据或合计不为 1、最终 SVG 计数超过蓝图计划，以及成稿中隐藏边、透明描边、透明泳道、改写概率和线宽。正例覆盖五种图示的真实 SVG 渲染及浏览器页面探针读取容量和语义标记。

验证命令：`npm test`、`CHROME_CHANNEL=chromium npm run test:render`、`CHROME_CHANNEL=chromium npm run test:upgrade-render`、`node scripts/sweep_forms.cjs --check`，另用系统 `skill-creator` 的 `quick_validate.py` 检查技能入口。浏览器测试需要本地 Chromium 能正常启动。

2026-09-23 实跑以上门禁均通过。两路独立只读审计分别检查实现和文档；审计复现的容量绕过、图示语义错配与可见性问题修复后，未发现剩余可复现的 P1/P2。目视检查了泳道、条件和层级样例；条件边标签的背景衬底经二次渲染确认不会被连线穿字。

这组结果证明规则被执行和反例被拦截。它不认证外部来源真实性，也不能保证任意真实业务报告的选图与视觉判断都正确。正式交付仍需按技能要求审阅最终 HTML/PDF。
