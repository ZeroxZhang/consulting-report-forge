# 全局规则一致性检查

检查日期：2026-09-22。范围包括技能入口、全部参考文档、制作模板、形式登记与布局图谱，并沿相关规则核对蓝图、内容编译、页面校验、审查要求及测试。重点检查的是规则是否误导选型与执行，不宣称覆盖所有图型的渲染质量。

| 发现 | 修正 |
|---|---|
| 实现入口被描述为图型能力上限 | 明确专用组件、自定义静态SVG及数据前提；修正误差棒、分面、路线图等错误表述 |
| 坡度图被限为排名、KPI必须有目标、文字需凑三条依据 | 同步修正登记与指南；区分特定组件结构与一般论证，保留充分的一至两条依据路径 |
| 分布、地理等语义只能硬归到其他类型 | 扩展自定义语义枚举；仍拒绝未知身份和没有权威输入的瀑布 |
| 内容重排满三页也被强制新增洞察 | 当前蓝图不以故事角色配额判断质量；保留主张、来源、标题与实际审查 |
| 布局报错引导使用无法适用的豁免字段 | 改为可执行的目录或custom区域路径 |
| 简单任务与独立复核要求前后不一致 | 按任务风险统一说明，复用时按角色覆盖并集核对 |
| 计算操作清单被误读为模型清单 | 明确复杂计算可在可复算脚本或工作表中完成，再登记结果与来源身份 |
| 新旧规则与模板并列暴露给制作者 | 统一当前模板与执行说明；兼容内容留在维护文档和测试夹具 |
| 瀑布说明仍让作者手填编译结果 | 统一为蓝图输入、编译派生、现场对账，不跳过数据合同 |

验证：确定性测试、浏览器回归、HTML/PDF集成与篡改反例，以及默认模板编译、本地链接和差异格式检查。具体命令为 `npm test`、`npm run test:render`、`npm run test:upgrade-render`；上述命令本次均实际执行通过；内容合同包含25项检查，浏览器瀑布绑定包含13项检查。实现限制与兼容维护约定见[维护边界](maintainer-contracts.md)。
