# 技能行为评估

`tasks.json` 是原始任务输入，使用干净上下文的实际 Agent 与当前 SKILL 执行。不要向制作者提供本轮诊断结论或预期答案。各次运行记下技能基线、模型/能力、材料、起止时间、返工与产物路径。全部数据为合成；用户 B/D 原稿仅在本机单独比较，不复制进仓库。

评估分三层，互相不能替代：

1. `npm test`：版本兼容、计算与合同、布局诊断、快照与复用的确定性测试。
2. `npm run test:upgrade-render`：真实浏览器生成 HTML/PDF，验证内容绑定、目录/custom 页面和篡改/打印反例。合成渲染样稿不是模型自动创作能力的证明。
3. 干净上下文执行 `tasks.json`：观察方法选择、推断边界、标题链、页面质量、实际返工。由不同实例审查原始材料与最终图像，逐项写出证据。脚本不能替人评分。

审查维度：业务问题是否回答、计算能否复算、事实/预测/假设是否一致、结论是否超出材料、标题与证据关系、布局/密度/可读性、HTML/PDF一致、是否触发无必要专家与重复整册构建。各维度分开报告，不用一个平均分掩盖严重错误。

单页修订：完成一次真实审查与快照后，仅修改一页源数据并重新编译、装配、验收。检查该页失效、未变化页能否继承、本次全局审查是否仍待完成；公共字体/CSS变化应保守失效。记录继承范围，不能用页数下降代替实际耗时测量。

若比较 A/B/C/D 或模型，需相同任务、材料、页数范围、模型与资源条件，至少重复多次。当前样稿不同题材且来自历史版本，只能支撑机制诊断与具体缺陷复现，不能支持总体质量排名或速度提升百分比。
