# 咨询级单页系统

> 一页不是一个容器；它是从**结论 → 主证据 → 解释/限制 → 来源**的可扫读论证。

## 页面骨架与视觉预算

普通正文页应让读者找到：**结论型标题 → 主展品 → 支持证据/关键限定 → 含义或行动 → 来源**。按真实关系安排阅读路径，支持证据可以在图内、图下或侧边，读者不应依赖讲解者猜测。

| 区域 | 应承担的责任 | 常见失误 |
|---|---|---|
| 标题区 | 用有依据的发现或明确研究问题建立阅读任务 | 写“市场分析”“AI趋势”等名词标题 |
| 主展品 | 第一眼证明标题中的核心关系 | 小图居中、无共同量尺、只做装饰 |
| 支持证据 | 给基准、分母、异常、条件、反例或时间维度 | 重复主图数字、堆文案卡 |
| 含义区 | 将发现转换为取舍、风险或行动 | 复述标题、堆“因此建议” |
| 来源区 | 给可核查出处和关键限定 | 微字、截断、与页码冲突 |

### 密度不是拥挤

| 密度 | 合理构成 | 适用页面 | 不可接受的替代 |
|---|---|---|---|
| `dense` | 主图 + 2个以上不同证据职责 + 明确含义/限制 | 核心诊断、路径选择、复杂比较 | 无关系的卡片、碎片化数字或微字表格 |
| `balanced` | 主图 + 一个有不同职责的支持单元 | 默认分析、机制、研究结论 | 只有一张小图，剩余空间空置 |
| `sparse` | 一个关键证据/判断 + 经解释的停顿 | 章节转折、单一重大结论 | 把缺证据或没做完包装成极简 |

证据单元记录的是证明职责，不等于独立卡片数：同一张图内的基准、限定或解释可以承担支持职责，无需为了满足密度声明拆成多个框。密度字段的数量约定见 `scripts/density_contract.cjs`；选择适合材料的档位，不用填充内容反推档位。

### 留白纪律

留白应有阅读用途，例如**分组、聚焦、比较间隙、节奏停顿、来源安全区**。先检查证据是否充分、主图能否充分展开和支持单元是否互补，再判断留白；不要靠统一填充率判定质量。

**空白度量是须人工处置的提示。** 浏览器记录页底余量或内容间隙后，要对实际整页作出保留、重排、合页或补证的判断；不能只写“合理留白”就算检查完成，也不需要为了通过机器阈值强改为 `sparse`。溢出、遮挡、微字、来源丢失与错误数值表达仍必须修复。空白诊断实现在 `scripts/browser_visual_policy.cjs`。

## 两种正式布局路径

先确定本页证据关系和内容容量，再选择目录布局或 `layout: "custom"`。两种路径同等有效；目录用于复用成熟结构，自定义用于按内容安排主图、支持带、嵌入注释或分面，不需要先证明目录“用不了”。

- **目录布局**：声明 `L01` 等目录 ID；`regions` 按序对应目录模块，沿用目录的槽位、几何与容量检查。实际 DOM 仍须与声明落位一致。
- **自定义布局**：声明 `custom`，用 `regions` 记录阅读区的 `slot`、`role`、`form`、`span`。`slot` 可为 `main/left/right/top/bottom/aside/full`；`role` 可为 `primary/support/context/evidence/implication`，全页恰有一个 `primary`；`span` 是正有限相对份额，不是固定十二栏坐标。HTML/CSS 实现实际几何，QA 实测是否可读、溢出或侵入来源区。

```json
{
  "page": 1, "layout": "custom", "form": "recipe.rankedBar",
  "proves": "同口径规模差异与基准共同支持本页判断。",
  "regions": [
    {"slot": "main", "role": "primary", "form": "recipe.rankedBar", "span": 3},
    {"slot": "bottom", "role": "support", "form": "html.table", "span": 1}
  ]
}
```

以上仅示意布局字段；页面仍须提供适用的密度、证据和来源声明。主图要有足够的真实绘图区，支持带应增加基准、限定或解释关系。并列三栏、左右分栏和连续重复都可以用于真实对照，是否采用由证据关系决定。图型种数、构图种数与重复次数仅进入诊断，不为满足配额添加组件或改换图型。

## 目录布局的版心与模块网格

当前运行时支持两种画幅：1280×720与1024×768；任意其他画幅尚无完整合同与验收实现，不能只改CSS即宣称支持。目录布局的正文区使用 12 栏 × 6 行整数网格，下面的几何与容量表用于目录选型和 DOM 对账；它们不限制 自定义阅读区必须落在这套网格上。

| | 16:9 | 4:3 |
|---|---|---|
| 画幅 | 1280×720 | 1024×768 |
| 版心（内边距 32/40/40/26） | 1200×662 | 944×710 |
| 栏 | 12 × 89 + 11 × 12 = 1200 | 12 × 64 + 11 × 16 = 944 |
| 行 | 6 × 71 + 5 × 12 = 486 | 6 × 80 + 5 × 16 = 560 |
| 标题带 | 128（1 行标题 87、2 行 112 都装得下，正文起点因此恒定在 y=160） | 120 |
| 来源带 | 48 | 30 |
| 纵向合计 | 128 + 486 + 48 = 662 | 120 + 560 + 30 = 710 |

两种画幅共用同一套 12×6 拓扑：换画幅只换像素换算，不换布局。所以目录里的 `{c, r, w, h}` 与画幅无关，一份布局目录同时服务两种画幅。

16:9 下，第 r 行第 c 栏的像素位置是 `x = 40 + (c−1) × 101`、`y = 160 + (r−1) × 83`；跨 w 栏宽 `101w − 12`，跨 h 行高 `83h − 12`。4:3 把 101/83 换成 80/96。

这张表的用处是**先约束、后填充**：选布局的那一刻就能判断"我要放的证据装不装得下这一格"，而不是排完版才发现放不下、再去缩字号。缩字号是这一环失守后的补救，不是设计。

### 槽位：一格允许装什么

目录布局给每格指定槽位，沿用该目录ID时应遵守对应形式与尺寸合同。如果内容需要不同形式，应换目录布局或声明自定义区域；表与图都能承担证据，不存在全局性的“表不能替图”。

| 槽位 | 它意味着什么 |
|---|---|
| `chart` | 把数据变成图形。带坐标轴的图要有足够的格 |
| `table` | 精确查数。读者要能逐个核对数字时用它，不要用图替代 |
| `diagram` | 表达机制、流程、层级或条件，不承担精确读数 |
| `kpi` | 少量关键指标，读数优先于趋势 |
| `timeline` | 时间轴、阶段与泳道，顺序本身就是论点 |
| `text` | 结构化文字：短判断、清单、条目 |
| `annotation` | 贴着展品的解读、口径、结论块 |
| `panel` | 通用并列格，接受任何已登记形式。论证不依赖某一格的具体形式时用它 |
| `head` / `source` | 由版心固定占用，不接受形式声明 |

### 类名契约：`html.*` 形式的结构

有些形式是**作者写 HTML、技能只给样式**（`kind: "html"`）。类名对不上就等于没有样式，也不会报错——所以这里是这些形式的唯一权威类名表。技能只样式化下列名字，其余类名由作者自定、技能不管。

| form | 结构 | 校验 |
|---|---|---|
| `html.kpi` | `.kpi-grid > .kpi-card > .kpi-label` / `.kpi-value` / `.kpi-note` | 否。卡数上限见容量表；`.kpi-grid` 按列流铺满整行，自定义列数时须复核卡数变化、换行与空列；默认样式采用自动列流 |
| `html.finding` | `.finding > .finding__verdict`＋`.finding__grounds > .finding__step`（内含 `.finding__rank` / `.finding__label` / `.finding__why`）＋`.finding__limit` | **是**：本组件要求判断、限定、至少3条依据及正确档位；依据较少时用 `html.text`，不为组件补造内容 |
| `html.table` | `.data-table`（`th` / `td` / `.num` / `.selected` / `.group`）；带数据条的用 `.analytical-table`（`caption` / `.column-unit` / `.table-bar` / `.total`） | 否 |
| `html.matrix` | `.evidence-grid`、`.microbar`、`.matrix-note`、`.decision-strip`、`.evidence-note`、`.status-good` / `.status-risk` / `.status-caution` | 否 |

**写样式时的字重陷阱**：`assets/consulting-layouts.css` 里写 `font-weight:700` 是可以的，但复用内置样式时应把选择器加入 `assets/deck-typography.js` 的归一化名单，或直接使用合同接受的正文400/500/600字重（`b,strong,.data-table th,.row-label,…` 那一行）——归一化把 700 拉回 600 才是字重合同的落点。名单漏了新选择器，成稿审计就会报"正文字重只能用 400/500/600"。（实测：`.status-label` / `.row-label` / `.analytical-table caption` 都靠这份名单归到 600。）

`panel` 是并列型布局的出口：当几格彼此等价时用它，而不是硬指定 `chart`——否则作者会被迫把表格塞进图表位。代价是约束变弱，使用时仍须明确各区域的实际证明职责。

### 目录中的铺排与留白

每条目录布局声明 `fill`。`tiled` 表示模块铺满 12×6；`open` 表示目录内有意留白，并用 `openWhy` 解释。这是目录自身的结构承诺，不能推导为每页实际内容必须填满模块，更不用于限制 自定义布局。留白的阅读效果仍须看真实页面。

## 布局：从这里选，不在这里列

**本文档不列目录布局清单。** 目录的唯一权威是 `assets/layout-atlas/catalog.json`；`assets/layout-atlas.html` 是它的图谱视图，由 `scripts/build_layout_atlas.cjs` 生成，`--check` 会在图谱与目录漂移时报错。自定义布局不需要增加目录条目。

选型顺序是**读者问题 → 证据与关系 → 表达形式与所需空间 → 目录或自定义布局**。确定母版职责后，比较主图、支持证据与来源是否能清楚放下；容量不足时调整组织和分页，不先锁格子再补内容。

布局按**族**组织，族说明的是"这一族在论证里干哪种活"：

| 族 | 干的活 |
|---|---|
| 甲 单证据统领 | 一个证据足够强，其余模块只做解读 |
| 乙 并列与对照 | 多个对象、方案或分面需要被平等地放在一起看 |
| 丙 矩阵与分面 | 两个维度同时在场，或同一对象要在多个维度上被查 |
| 丁 递进与拆解 | 顺序、层级或拆解本身就是论点 |
| 戊 主辅互补 | 一个主展品加一组职责不同的支撑 |
| 己 综合与研判 | 把多个判断收拢成一个取舍或一个结论 |
| 庚 执行与治理 | 责任、时序、门槛与台账 |
| 辛 论述与查证 | 以文字与来源承担论证，图不是主角 |
| 结 结构页 | 封面、目录、章节导读——不承担证据 |

打开图谱选：左侧按母版分组，每条的用途、阅读路径、代价、禁用条件、逐格槽位与容量都在同一页上。同几何但语义不同的布局，图谱会直接点出来——按论证需要选，不要按长相选。

同宽三栏可以支持同口径对照；左右分栏可以支持证据与解读。不要把它们当默认答案，也不要为了避免重复而禁用。装饰性大引号、无语义图标阵列、整页背景纹理、彩色边条或用颜色替代标签不能增加证据。

## 图形与信息图严谨性

1. **比较**：使用共同基线、排序规则和直接标签；不要让颜色或面积独自承担大小比较。
2. **趋势**：区分实际、预测、目标、缺失；预测在视觉和文字上都应有边界。
3. **构成**：仅在类别互斥且可加时使用份额表达；否则使用并列基准或嵌套关系。
4. **贡献**：瀑布和桥接必须能对账；贡献排序若声称完整分解，也须给出总量与覆盖边界——起点、增量、终点要对得上，缺失不等于 0，说不清的差额必须作为独立节点出现并写明来路，不许悄悄并进最后一根柱子。贡献项上限 16 条（画布上另有起点与终点两根柱，有残差柱再减 1），这是当前瀑布合同的节点上限。超限可有依据地归组并提供明细，或分成分别可对账的页面；不得无依据合并或静默截断。描述性分解不可称为因果归因。数据侧的完整规矩见 [瀑布数据合同](waterfall-bridge.md)。
5. **流程/机制**：箭头写明流向、条件或责任；等宽节点和连接线不能暗示同等规模、时长或因果。
6. **矩阵**：每条轴、每个评分或热力色必须有明确业务定义；没有可靠评分就改为定性分类并明示。
7. **表格**：单位、期间、对齐、缺失含义、总计与高亮规则必须可解释；关键列保持少，复杂细节放附录。

## 排印、色彩与可访问性

- 建议控制为一个标题级、两个正文级和一个辅助注释级；复杂层级可按阅读需要调整，仍需实际验证可读性；同一语义角色用一致字号、字重和色彩。
- 默认使用明亮底色 + 深色正文；强调色仅用于分组、状态或被直接标签补足的重点。不得出现浅色背景上的浅色文字，或深色背景上的深色文字。
- 不把决定判断的信息放进小于可读阈值的脚注；来源可以紧凑，但不得遮挡或截断。
- 表格、矩阵和图表应允许读者在灰度、投影或打印中区分状态：采用文字、线型、形状或直接标签做冗余编码。
- 同一页中对象的边界、文字基线、比较轨道和数字小数点应对齐；用真实绘图区而不是外框检查。

## 一页制作顺序

1. 先写标题、`proves` 和主展品的最小数据需求。
2. 找出能限制、比较或推进主结论的支持证据，按真实关系组织，不能重复主图数字凑单元。
3. 仅当需要把判断转为取舍/行动时增加 `implication` 单元。
4. 按内容容量选择目录或自定义布局；让主展品充分展开，支持带和注释紧随需要解释的位置。一次规划数页，核对合页是否更利于理解。
5. 标出阅读路径、来源安全区与留白用途。重复结构若能建立稳定比较关系，可以保留。
6. 在任务实际画幅预览中检查整页；区分证据不足、图形未充分展开与有用途的停顿，分别补证/合页、调整绘图区或保留，不用空框填白。
7. 跑 QA：目录布局逐格核对实际矩形，自定义布局实测可读性、溢出、来源与呈现语义。处理诊断提示后逐页目视检查，测试通过不替代成品判断。
