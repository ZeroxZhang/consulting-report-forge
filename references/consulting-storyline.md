# 咨询叙事与决策架构

咨询材料的基本单位是**有依据、可检验、能推进理解或决策的一步推理**。本文在关键分析形成后用于组织全篇；方法与计算见[分析方法](analysis-methods.md)。

## 先形成答案，再组织表达

从用户目标提取读者要理解或决定的问题，再用已有证据形成 `governingThought`：对象、判断与必要条件清楚，不能只是“行业趋势与建议”。决策任务的 `decision` 写批准、选择、停止、投入或验证什么；研究任务写这份研究要支持的判断，不强造投资推荐。

研究与表达顺序不同。已有初步答案时自上而下检查支持与反证；材料零散时自下而上比较、归组、综合。未经验证的答案只是工作假设，不能先把标题定死再挑支持材料。证据不足时允许有限判断、竞争解释或明确未知。

将每页标题连起来读。它们应构成一段能独立成立的论证，而不是重复章节名。若标题连读后仍像“市场概览—竞争分析—建议”，说明尚未形成故事线。

## 默认决策弧线

根据材料选择其中一条，而不是机械套用全部页面。

| 弧线 | 适用问题 | 最小推理顺序 |
|---|---|---|
| **机会到取舍** | 增长、市场进入、投资方向 | 决策问题 → 机会规模/结构 → 竞争或约束 → 可选路径 → 推荐与行动门槛 |
| **问题到修复** | 经营诊断、效率、转型 | 目标/现状 → 症状 → 根因/机制 → 方案取舍 → 路线图与验证指标 |
| **不确定性到下注** | 情景、技术、政策、战略风险 | 不确定性 → 影响暴露 → 情景差异 → 不后悔动作/触发器 → 治理与监测 |
| **证据到观点** | 行业研究、专家报告、学术型材料 | 定义与口径 → 事实模式 → 机制/异质性 → 反证与边界 → 对研究或产品的含义 |

弧线是论证分工，不是必填页型配额。研究应推进到洞察、边界或下一步验证；决策材料应给出真实选项与取舍。已有内容重组不强加新研究，没有实施任务就不虚构负责人、预算和日期。蓝图字段及机器约束以模板与校验器为准，不通过伪造内容补齐结构。

## 先检查证明关系，再分页面

围绕关键判断做三项检查：

1. **纵向支持**：每个上层判断被什么事实、计算与推理支持？上层不能比下层更确定；从事实到模式、解释、建议，每一步需要依据。
2. **横向关系**：同组是并列理由、组成部分、时间步骤还是演绎前提？分组使用同一维度，交互依赖显式说明；不要把事实、风险、动作混成三个“方面”。MECE用于分类查漏，不机械套在因果链或演绎链上。
3. **覆盖与反证**：读者的重要问题是否回答，反证和限制是否影响主判断，未采用材料有无理由？多个来源转述同一材料不算独立支持。

将结果统一写回蓝图的总判断、页面 `proves` 与关键主张；不另写一份会与蓝图漂移的故事线。逐页想清“读者现在有什么疑问、本页新增什么理解、下一页为什么必要”。总览说明系统，证据页展开差异，机制页解释条件，综合页形成取舍。

相邻页只重复同一摘要时合并或重新分工；不同的数字、图型不自动构成不同证明任务。读者需要同时比较的对象尽量保留共同量尺；一页无法兼顾数量与机制时可拆成相邻两页，明确二者的证明分工。

## 页面角色与禁止替代

| 页面角色 | 读者需要获得什么 | 适用表达 | 不能替代为 |
|---|---|---|---|
| `cover` | 决策题、范围和阅读预期 | 简洁题目、范围、核心问题 | 大段摘要或装饰图堆砌 |
| `section` | 为什么切换叙事阶段 | 阶段判断、1个问题、极少量线索 | 无内容的彩色隔页 |
| `analysis` | 一个关系是否成立 | 比较、趋势、机制、分布或精确表 | 一页罗列多个事实 |
| `decision` | 选项与取舍为何不同 | 决策树、场景矩阵、权衡图 | 结论口号 |
| `action` | 先做什么、如何证明有效 | 优先级、路线图、责任与验证门槛 | 无依赖和所有者的愿望清单 |
| `risk` | 什么会使结论失效 | 敏感性、阈值、反例、触发器 | 末页泛化风险提示 |
| `appendix` | 何处可复核 | 方法、数据、口径、明细 | 把关键限制藏到附录 |
| `close` | 读者离场时应记住什么 | 一句收束判断与下一步 | 重复封面 |

## 标题纪律

标题优先写有依据的发现，需要时补含义；探索页可以用中性问题。标题中的比较、趋势、条件和强词都要在展品中有对应对象，不能只在旁边的段落里成立。

| 弱标题 | 合格标题 | 需要的证据 |
|---|---|---|
| 市场概览 | 高增长集中在两个可验证场景，第三场景尚无可比口径 | 共同量尺的比较与口径注释 |
| AI 影响 | AI缩短制作环节，但人工批准仍是高风险动作的控制点 | 流程、控制点与产品边界 |
| 下一步建议 | 先在高信号场景试点，并以增量测量而非平台归因决定扩张 | 优先级、验证指标、停止条件 |

以下词语默认需要更强证据或限定：**驱动、导致、主要、唯一、显著、确定、最优、必然、全面、行业平均**。不能证明时，改成事实描述、条件句或研究限制。

## 反证与收束

重大判断说明：什么事实会推翻它，现有反证为何不足以推翻，哪个未知可能改变选择。把限定放在对应分析页或验证安排中，不藏到附录，也不要让全篇变成“尚不能证明”的提示集。

建议比较现状与可行备选，说明收益、成本、风险、现金与执行条件。需要实施计划时再落实对象、动作、责任角色、依赖、时间窗和验证/停止条件；未确认的负责人、日期与预算标为待定，不编造承诺，也不把所有建议强改成实验。

观察指标要区分**事实基准、作者建议的复查触发器、经过验证的决策条件**。自设阈值应解释依据与下一步检查，不能从“增速跌破某值”直接推出补贴抢装或需求衰退；没有阈值依据时可以用待验证条件，不制造精确数字。

完成后连读标题检查推进，再回看每页实际证据检查支持。标题流畅不等于推理正确；复杂或重大判断按[协作](collaboration.md)前置独立质疑，最终成稿仍需实际审查。
