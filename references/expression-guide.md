# 表达选型：从关系到证据

> 先问“读者必须看出什么关系”，再问“用什么图”。图型是证据的形状，不是装饰。
> `assets/deck-forms.js` 定义可声明的实现入口；自绘图表用其中的 `svg.custom`，同时声明实际表达与数值语义。登记表不限制你只能使用现成图形。
> **按表达是否适合证据验收**：图型种数与重复次数进入诊断，合理的同尺度分面和连续比较可以保留；不要求为了配额换图。

## 快速选择

下表按“关系”给出现成形式。**加粗**的是首选；每行都写了本技能的真实 `form` id，可直接填入蓝图的 `visual.form`。

| 关系 | 本技能可用形式 | 先检查什么 | 不要这样做 |
|---|---|---|---|
| 对象比较、排名 | **`recipe.rankedBar`**、`recipe.groupedBar`、`kit.dumbbell`、`kit.slope` | 共同基线、固有顺序、Top N 是否遗漏重要对象、两期是否同量尺 | 用排序破坏时间或流程顺序 |
| 时间趋势、周期 | **`recipe.timeSeries`** | 连续/离散期间、缺失/零/预测、系列遮挡、离散点是否被平滑 | 用平滑线伪造连续变化 |
| 构成、占比、层级 | **`kit.shareBar`**（单期）、**`kit.stacked`**、`kit.mekko`、`recipe.composition`、`precision.stacked`；层级用 `kit.tree`、`recipe.tree`、`diagram.hierarchy` | 部分是否互斥可加、整体定义、类别规模、窄列小片是否放得下 | 对不可相加的数据画份额图 |
| 分布、离散、异常 | **`recipe.histogram`** | 样本量、分箱或估计规则、异常定义 | 只报均值而掩盖决定判断的分布 |
| 相关、多变量、群组 | **`recipe.scatter`**、`kit.heatmap`、`recipe.heatmap` | 变量类型、阈值依据、相关不等于因果、缺失格是否被当成 0 | 用视觉团簇宣称统计显著群体 |
| 目标、绩效、状态 | **`kit.bullet`**、`html.kpi` | 单位、期间、目标基准、正负业务语义 | 给任意数值套 0–100% 仪表盘 |
| 增减、贡献、桥接 | **`kit.waterfall`**、`precision.waterfall`、`precision.columns` | 起点/终点能否对账、分解方法、残差、是否闭合 | 将描述性拆分说成因果归因 |
| 流程、流量、转化 | **`recipe.sankey`**、`diagram.process`；阶段流程 `kit.processFlow`；多主体 `kit.swimlane`、`diagram.swimlane`；分支 `diagram.condition` | 阶段口径、守恒边界、真实顺序、节点/边是否守恒无环 | 用等宽箭头伪装定量流量 |
| 项目、时间、定性结构 | `diagram.condition`、`diagram.hierarchy`、`html.matrix`、`html.finding`、`html.text` | 日期、依赖、责任、定性/定量身份 | 把无证据的层级画成“金字塔结论” |
| 精确查值、互补证据 | **`html.table`**、`kit.comparisonTable`、`html.matrix` | 读者是否需逐格核对、两个展品是否分工、一列是否只有一种单位 | 重复主图数字填版面，或为图型种数强换不适合的表达 |
| 机制、因果结构 | **`diagram.mechanism`** | 每条边是否写了含义与证据状态、循环是否标了反馈 | 用箭头数量或粗细暗示因果强度 |

**没有专用组件，不等于不能制作。** 上表列的是已封装的实现入口，不是允许使用的图型白名单。箱线、小提琴、漏斗、甘特、地图、区间图等可按数据与任务需要制作，具体路径见「词汇表之外的表达」。

需要区分三件事：

- **已有组件**：使用现成输入、几何和检查，减少实现工作。
- **自定义实现**：通过自绘或组合SVG，也可使用 `scripts/render_echarts_svg.cjs` 的原生 `option` 入口生成静态SVG；未单独登记的实现按 `svg.custom` 声明。原生入口不代表任意配置都已验证，作者须检查数据、标签和最终HTML/PDF。
- **本次数据或编码不适合**：缺少样本、区间含义、时间或地理数据，或编码会误导时，应补数据、缩小主张或换合适表达。这是当前证据的限制，不是永久禁止某种图型。

`assets/deck-forms.js` 是实现入口登记；布局目录记录槽位与容量。不要把登记数量当成能力上限，也不要为了沿用已有组件而丢掉读者需要的关系。

## 本技能的表达词汇

12 个族、35 个已登记实现入口（含自定义入口）。这些不是35种图型的能力上限。族决定它在论证中承担什么角色；下列容量约束属于对应组件，超限时重排、分面或换实现。自定义实现仍须通过实际可读性检查，不得借换名掩盖过密，也不能改成表格后沿用原图型名称。

### 比较与排名（comparison）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.rankedBar` | 排序优先，读者要读名次与差距 | ≤ 24 项，正文宜更少 |
| `recipe.groupedBar` | 少数类别 × 少数系列的分组对照 | ≤ 12 类 × 4 系列 |
| `kit.dumbbell` | 两期或两对象同一量尺上的一对一比较 | 行 ≤ 14；两期同口径同量尺 |
| `kit.slope` | 比较同量尺两期的数值或名次变化 | 行 ≤ 10；同量尺两期数值或名次；横距不编码连续时间 |
| `kit.waterfall` | 从起点经增量到终点的桥接（构建期） | 贡献项 ≤ 16（另占起点与终点，有残差柱再减 1）；不闭合不做 |
| `precision.waterfall` | 同上，但需要累计连接或更精确的标注 | 须闭合；累计连接只用于瀑布；贡献项 ≤ 16（另占起点与终点）；不接受破轴 |
| `precision.columns` | 需要小计、断轴或 Δ 标注的精确数值柱 | ≥ 400×260；类别 ≤ 4 行 |

> **瀑布的数据下限不是“有数字就行”**：起点、增量、终点必须能对上账才允许出图，缺失不等于 0，差额也不许自动抹平。原始记录怎么进、费率怎么加权、残差什么时候才承认，见 `references/waterfall-bridge.md`——那是瀑布数据合同的唯一权威；渲染器只负责把内核判定过的几何与文本画出来，不自己再算一遍。

### 趋势（trend）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.timeSeries` | 连续期间上的演变与拐点 | ≤ 36 期 × 5 系列，更多分面 |

### 构成（composition）

| form | 何时用 | 容量上限 |
|---|---|---|
| `kit.shareBar` | **单期**构成：一份整体切给哪几块，各占多少 | 1–2 条 × 系列 ≤ 6；段宽即份额；条厚按格宽定，不撑满格子；单条时省略类别行；三期以上改用 `kit.stacked`；两条更吃格子，放不下会报错 |
| `kit.stacked` | 绝对量的构成随时间或类别变化 | 列 ≤ 12 × 系列 ≤ 6；仅非负组成；小片与零值走引线通道 |
| `kit.mekko` | 份额与列规模同时有意义 | 列 ≤ 6；窄列与小片自动改走同侧引线通道，通道放不下时报错 |
| `recipe.composition` | 堆积或 100% 堆积，类别较多 | ≤ 12 类 × 6 系列 |
| `precision.stacked` | 需要层间比较的精确堆积 | 仅非负组成；列内须列全系列 |

### 分布（distribution）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.histogram` | 读者要看离散形态、尾部或双峰 | 须已正确分箱，不从均值伪造 |

### 相关与矩阵（correlation）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.scatter` | 两个连续变量的关系；气泡可加第三维 | > 15 点只标关键点 |
| `kit.heatmap` | 离散矩阵的整体形态（构建期） | ≤ 160 格；固定 domain；只接受有限数值，未观察／缺失用自定义 SVG 或 HTML 单独编码 |
| `recipe.heatmap` | 同上，数据驱动 | ≤ 160 格；只接受有限数值，未观察／缺失用自定义 SVG 或 HTML 单独编码 |

### 流向（flow）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.sankey` | 多对多的量流与损耗 | ≤ 30 节点 / 60 边；须守恒无环 |
| `diagram.process` | 流程与资金转移 | 无量化就不给连线加宽度 |

### 层级（hierarchy）

| form | 何时用 | 容量上限 |
|---|---|---|
| `kit.tree` | 层级拆解（构建期） | ≤ 48 节点；每层同一拆分逻辑 |
| `recipe.tree` | 同上，数据驱动 | ≤ 48 节点 |
| `diagram.hierarchy` | 能力／层级地图 | 区分包含、依赖、必要条件 |

### 达成度（kpi）

| form | 何时用 | 容量上限 |
|---|---|---|
| `kit.bullet` | 实际 vs 目标 vs 分档 | 指标 ≤ 6；分档须另有业务定义 |
| `html.kpi` | 少量核心指标的卡片组 | 建议 ≤ 5 张卡；实际值需单位与期间，目标仅在有依据时添加 |

### 机制与流程（diagram）

| form | 何时用 | 容量上限 |
|---|---|---|
| `diagram.mechanism` | 因果链条与反馈回路 | 边须写含义与证据状态；循环标反馈 |
| `kit.swimlane` | 单节点单元格的泳道（构建期） | 单元格仅 1 节点；复杂分支换专门路径 |
| `diagram.swimlane` | 多主体跨阶段的职责与交接 | lane 编码主体、stage 编码阶段 |
| `kit.processFlow` | 3–6 段的线性阶段 | 3–6 段线性；等宽不表示等时长 |
| `diagram.condition` | 条件分支与决策树 | 决策节点与结果分开；概率缺依据就保留分支 |

### 精确查数（table）

| form | 何时用 | 容量上限 |
|---|---|---|
| `html.table` | 读者要逐格核对数值 | 一列一种单位；总计由作者提供 |
| `kit.comparisonTable` | 少量对象的属性对照 | 高度由内容决定，须自行分页 |
| `html.matrix` | 评估矩阵、优先级矩阵、RACI | 权重与评分锚点须透明 |

### 结构化文字（text）与作者实现（custom）

| form | 何时用 | 容量上限 |
|---|---|---|
| `html.finding` | 有判断、有可数的依据、也有边界 | 本组件要求判断／依据／限定三级和至少3条依据，建议3–5条；更少依据用 `html.text`，不凑数 |
| `html.text` | 文字比图形更直接地表达论证或限定 | 适合精确措辞、解释、引文、假设和有限依据；是否画图由阅读任务决定 |
| `svg.custom` | 按证据需要自绘图表、分面或组合表达 | 几何与数值语义由作者负责，须实际看图；不能绕过对账、尺度和来源检查 |

## 选型程序

1. 写下页面主张，以及它要求读者看出的**一个**关系（蓝图的 `proves`）。
2. 写下数据的真实身份：观测单位、期间、分母、单位、缺失语义、是否互斥可加。
3. 排除：数据不支持、口径不可比、编码误导、静态不可读、容量超限的方案。
4. **按证据关系展开候选**——同时考虑现成组件与自定义表达，不只从登记表中挑。比较实现成本，但不能为少写代码牺牲关键关系。
5. 在剩余候选中比较：决策任务匹配度、比较精度、重点识别、信息容量、学习成本。
6. 写出主表达。只有存在实质取舍时，才记录一个备选及其胜出条件。
7. 检查标题、图例、标签、尺度、注释和来源是否共同证明同一主张；检查容量是否真的放得下。

## 数据契约

形式对数据有最低要求。字段不满足时先回去补数据或改主张，不要画一张看起来对但语义错的图。

| 族 | 最低需要 | 额外条件 |
|---|---|---|
| comparison | 1 个类目字段 + 1 个数值字段 | 哑铃/坡度需每行两个同量尺数值；瀑布需起点 + 有符号增量 + 能对账的终点 |
| trend | 1 个有序时间字段 + ≥1 数值 | 期间必须连续或显式标出缺口；预测段须与实测分开编码 |
| composition | 部分互斥、可加，且整体有定义 | 份额与Mekko使用非负部分，Mekko另需列规模；正负贡献应采用明确区分方向的变化表达，不强塞入非负构成组件 |
| distribution | 原始观测、已声明分箱或足以支撑所选图形的统计摘要 | 样本量、分箱规则、异常定义必须可写进注释 |
| correlation | 散点需成对变量；矩阵需有业务定义的行列与格值 | 现成热力组件要求有限数值；自定义实现可单独编码缺失，不得把缺失当0 |
| flow | 节点 + 有意义的边；定量流图另需流量 | 现成桑基要求无环、守恒；定性流程不要求虚构数值，边宽不得暗示未测得流量 |
| hierarchy | 父子边 | 每层同一拆分逻辑，不得混用包含/依赖/必要条件 |
| kpi | 实际值 + 单位 + 期间；目标比较另需真实目标 | 目标与分档边界须有业务定义；没有目标不虚构 |
| diagram | 节点 + 带语义标签的边 | 箭头须标作用、交接、包含、前置条件或证据状态 |
| table | 每列一种单位 | 缺失、零值与不适用要能区分 |
| text | 定性主张、引文、解释、假设或有限依据 | `html.finding` 的条数是组件约定；一至两条充分证据也可用 `html.text`，不得编造更多依据 |

## 反模式

以下做法在本技能里一律不允许，出现即返工：

- **伪 3D 定量图**、装饰性色条、顶部色条数字卡、无意义图标阵列。
- **气泡按半径映射数值**——必须按面积映射，否则数值被平方放大。
- **用双轴制造相关**——任意缩放造成的视觉贴合不证明相关；确需双轴时明确单位、映射与用途，优先评估同轴或分面。
- **构成图用于不可加或非互斥的数据**——份额图的前提是部分互斥且可加。
- **雷达图**用于维度多且尺度不可比的场合。
- **平滑线伪造连续变化**，把离散点之间的连线暗示为已观测的连续过程；连接离散期间可以表达顺序，但须标出观测点和缺口。
- **等宽箭头或等宽节点暗示定量、时长、规模或因果强度**。
- **力导向距离被当作业务距离**。
- **给任意数值套 0–100% 仪表盘**。
- **只报均值而掩盖决定判断的分布**。
- **未说明的截断量尺**；柱与条默认以零为基线，非零折线起点必须显著说明。
- **依赖悬停才能读到的关键信息**——静态读者不能悬停，关键值必须直接显示。
- **用重复内容填页面**——重复图型可以帮助同口径比较；重复数字与重复边界说明不能自动算作新增证据。种数和重复是审稿提示，不是更换图型的命令。
- 用拉伸容器或改配色掩盖证据不足。真实主图应有足够绘图区，扩大过小的绘图区是正常的布局调整。

## 静态媒介编码底线

- 用共同位置或长度做精确比较；柱、条默认以零为基线。非零折线起点必须显著说明。
- 将实际、预测、缺失、零值、百分比和百分点分开编码，并直接写出单位、期间和基准。
- 多系列遮挡时改小多图、分面或总览加局部，而不是不断加颜色。
- 桑基、瀑布与份额图先验证流量、总量和端点；不隐藏残差、损耗、补充或不可解释部分。
- 颜色只辅助语义，不能成为唯一含义；灰度或投影环境下仍须可解释。
- 容量是硬约束：超过上限时在同一表达内重排、分面或换实现，**不要改成表格再沿用原图型名称**。

## 词汇表之外的表达

本节说明缺少专用封装时如何实现，以及哪些替代会损失信息。下列图型都不因未登记而被禁止；是否采用取决于数据前提、静态可读性和实际实现质量。

| 表达需求 | 可用实现路径 | 数据与表达前提 |
|---|---|---|
| **箱线、小提琴、蜂群、ECDF、分位带** | `svg.custom`：自绘、组合或经验证的原生配置 | 箱线需分位数与须线定义；小提琴需密度估计及参数；蜂群、ECDF需观测或充分分布信息；分位带需各位置的分位数。直方图适合分箱分布，但不等价于上述所有关系 |
| **小多图、分面** | 复用组件并排布，或以 `svg.custom` 声明整组 | 分面是组织方式，不是缺失的单图组件。跨面板比较绝对大小时共用量尺；采用独立量尺时须显著说明，不能直接比较高度 |
| **漏斗** | `svg.custom`；也可用阶段条形图明确展示数量与转化率 | 核对同一群体、阶段顺序、期间与分母。单路径漏斗与多路径桑基回答的问题不同，不能只因都有流失就互换 |
| **甘特、路线图** | 甘特用 `svg.custom`；定性路线图可用阶段流程、泳道或自定义区域 | 甘特需开始/结束时间及有依据的依赖；路线图可以只表示阶段与里程碑，不必强造精确日期或按比例时长 |
| **地理、位置**：分级设色、比例符号、流向、网格 | `svg.custom`，按任务加载或绘制地理几何 | 需位置、区域或网格数据，并检查坐标、投影、边界来源及数值尺度；只有区域排名需求时，条形图可能更合适 |
| **区间、不确定性**：区间点、误差棒、置信带、森林图 | `svg.custom`：点线组合、区间带或经验证的原生配置 | 点估计加误差棒可以编码区间，须说明上下限含义与置信水平（如适用）；范围、标准差、标准误和置信区间不可混用 |
| **龙卷风图** | `svg.custom`，通常用围绕基准的双向条形 | 显示输入变化对输出的敏感性；需明确基准、变化范围及其他变量是否固定，不自动代表概率区间 |
| **网络、生态、关系**：节点连线、二部图、弦图 | `svg.custom`：显式布局、自绘或经验证的原生配置 | 节点与边须有明确定义，方向和权重有依据；布局距离不自动等于业务距离，线多也不证明因果 |
| **矩形树图（treemap）** | `svg.custom`，保留面积编码 | 需可汇总的层级与非负规模。普通树图可表达层级，但若规模比较是核心，就不能当成等价替代 |
| **阶梯线** | `svg.custom` 或经验证的阶梯配置 | 若数值在事件之间保持不变，应编码实际跳变时点；普通折线会暗示中间插值，不能随意替代 |
| **四象限** | `recipe.scatter` 配合参考线与标注，或 `svg.custom` | 两个维度与阈值依据须明确；阈值不自动构成因果或投资建议 |
| **转移矩阵、队列留存图、邻接矩阵** | `kit.heatmap`／`recipe.heatmap`，必要时 `svg.custom` | 行列、分母、方向与对称性按实际数据说明。现成热力组件只接收有限值，未观察、未成熟队列和不适用格不得填零 |
| **日历热力** | 数据按日历排布后复用热力组件，或 `svg.custom` | 明确日期、星期起点、月份边界、缺失日与非日期空格；普通矩阵不会自动产生正确日历结构 |

**现成实现可作为优先候选**：桥接与增量分解有 `kit.waterfall`／`precision.waterfall`；差额标注有 `precision.columns` 的 Δ 入口；排名迁移有 `kit.slope`；两期对比有 `kit.dumbbell`。按实际需要决定是否复用，使用自绘实现也必须保持这些关系的数值语义。

蓝图写 `visual.form: "svg.custom"`，同时填写 `visual.semanticType` 及表达理由。`visual.layout: "custom"` 是另一件事，表示自定义页面区域，并不指定图型。用 `rationale` / `visual` 说明实际表达、选择理由与几何编码依据；自绘是正式实现路径，不需要把它包装成能力降级。坐标、量尺、标签、零基线、单位、期间和来源仍须遵守上面的编码底线。自绘瀑布仍需对账，自绘份额图仍需互斥可加，自绘气泡仍按面积映射；不能靠更名绕过数据合同。静态媒介不能悬停，关键值必须直接标注。
