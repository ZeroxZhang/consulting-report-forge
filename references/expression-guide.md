# 表达选型：从关系到证据

> 先问“读者必须看出什么关系”，再问“用什么图”。图型是证据的形状，不是装饰。
> 本技能的选型范围是封闭的：`assets/deck-forms.js` 登记的 33 个形式就是可直接声明的全集，校验会拒绝表外形式。

## 快速选择

下表按“关系”给出现成形式。**加粗**的是首选；每行都写了本技能的真实 `form` id，可直接填入蓝图的 `visual.form`。

| 关系 | 本技能可用形式 | 先检查什么 | 不要这样做 |
|---|---|---|---|
| 对象比较、排名 | **`recipe.rankedBar`**、`recipe.groupedBar`、`kit.dumbbell`、`kit.slope` | 共同基线、固有顺序、Top N 是否遗漏重要对象、两期是否同量尺 | 用排序破坏时间或流程顺序 |
| 时间趋势、周期 | **`recipe.timeSeries`** | 连续/离散期间、缺失/零/预测、系列遮挡、离散点是否被平滑 | 用平滑线伪造连续变化 |
| 构成、占比、层级 | **`kit.stacked`**、`kit.mekko`、`recipe.composition`、`precision.stacked`；层级用 `kit.tree`、`recipe.tree`、`diagram.hierarchy` | 部分是否互斥可加、整体定义、类别规模、窄列小片是否放得下 | 对不可相加的数据画份额图 |
| 分布、离散、异常 | **`recipe.histogram`** | 样本量、分箱或估计规则、异常定义 | 只报均值而掩盖决定判断的分布 |
| 相关、多变量、群组 | **`recipe.scatter`**、`kit.heatmap`、`recipe.heatmap` | 变量类型、阈值依据、相关不等于因果、缺失格是否被当成 0 | 用视觉团簇宣称统计显著群体 |
| 目标、绩效、状态 | **`kit.bullet`**、`html.kpi` | 单位、期间、目标基准、正负业务语义 | 给任意数值套 0–100% 仪表盘 |
| 增减、贡献、桥接 | **`kit.waterfall`**、`precision.waterfall`、`precision.columns` | 起点/终点能否对账、分解方法、残差、是否闭合 | 将描述性拆分说成因果归因 |
| 流程、流量、转化 | **`recipe.sankey`**、`diagram.process`；阶段流程 `kit.processFlow`；多主体 `kit.swimlane`、`diagram.swimlane`；分支 `diagram.condition` | 阶段口径、守恒边界、真实顺序、节点/边是否守恒无环 | 用等宽箭头伪装定量流量 |
| 项目、时间、定性结构 | `diagram.condition`、`diagram.hierarchy`、`html.matrix`、`html.text` | 日期、依赖、责任、定性/定量身份 | 把无证据的层级画成“金字塔结论” |
| 精确查值、互补证据 | **`html.table`**、`kit.comparisonTable`、`html.matrix` | 读者是否需逐格核对、两个展品是否分工、一列是否只有一种单位 | 用重复图表填页面 |
| 机制、因果结构 | **`diagram.mechanism`** | 每条边是否写了含义与证据状态、循环是否标了反馈 | 用箭头数量或粗细暗示因果强度 |

**上表没有覆盖到的关系，本技能多半也没有原生形式**——分布离散度（箱线／小提琴／蜂群／ECDF）、小多图与分面、漏斗、甘特与路线图、网络与节点连线、地理与地图、区间与不确定性等。这些**全部见末尾的「词汇表之外的表达」**，那里逐条写明哪些必须走 `svg.custom`、哪些可以用现成形式诚实顶替。

> 此处**故意不再列一份平行清单**：`assets/layout-atlas.html` 的形式表就是因为与词汇表平行维护而腐烂过（曾少 2 条）。缺口只有一处权威来源，就是末尾那一节。

## 本技能的表达词汇

12 个族、33 个形式。族决定它在论证中承担什么角色；容量上限是硬约束，超了要在**同一表达内**重排、分面或换实现，不能改表降级。

### 比较与排名（comparison）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.rankedBar` | 排序优先，读者要读名次与差距 | ≤ 24 项，正文宜更少 |
| `recipe.groupedBar` | 少数类别 × 少数系列的分组对照 | ≤ 12 类 × 4 系列 |
| `kit.dumbbell` | 两期或两对象同一量尺上的一对一比较 | 行 ≤ 14；两期同口径同量尺 |
| `kit.slope` | 只关心排序迁移，不关心横距 | 行 ≤ 10；只比较排序迁移，不比横距 |
| `kit.waterfall` | 从起点经增量到终点的桥接（构建期） | 贡献项 ≤ 8；不闭合不做 |
| `precision.waterfall` | 同上，但需要累计连接或更精确的标注 | 须闭合；累计连接只用于瀑布 |
| `precision.columns` | 需要小计、断轴或 Δ 标注的精确数值柱 | ≥ 400×260；类别 ≤ 4 行 |

### 趋势（trend）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.timeSeries` | 连续期间上的演变与拐点 | ≤ 36 期 × 5 系列，更多分面 |

### 构成（composition）

| form | 何时用 | 容量上限 |
|---|---|---|
| `kit.stacked` | 绝对量的构成随时间或类别变化 | 列 ≤ 12 × 系列 ≤ 6；仅非负组成；小片与零值走引线通道 |
| `kit.mekko` | 份额与列规模同时有意义 | 列 ≤ 6；窄列与小片自动改走同侧引线通道，通道放不下时报错 |
| `recipe.composition` | 堆积或 100% 堆积，类别较多 | ≤ 12 类 × 6 系列 |
| `precision.stacked` | 需要层间比较的精确堆积 | 仅非负组成；列内须列全系列 |

### 分布（distribution）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.histogram` | 读者要看离散形态、尾部或双峰 | 须已正确分箱，不从均值伪造 |

### 相关与矩阵（correlation）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.scatter` | 两个连续变量的关系；气泡可加第三维 | > 15 点只标关键点 |
| `kit.heatmap` | 离散矩阵的整体形态（构建期） | ≤ 160 格；固定 domain；只接受有限数值，未观察／缺失用自定义 SVG 或 HTML 单独编码 |
| `recipe.heatmap` | 同上，数据驱动 | ≤ 160 格；只接受有限数值，未观察／缺失用自定义 SVG 或 HTML 单独编码 |

### 流向（flow）

| form | 何时用 | 容量上限 |
|---|---|---|
| `recipe.sankey` | 多对多的量流与损耗 | ≤ 30 节点 / 60 边；须守恒无环 |
| `diagram.process` | 流程与资金转移 | 无量化就不给连线加宽度 |

### 层级（hierarchy）

| form | 何时用 | 容量上限 |
|---|---|---|
| `kit.tree` | 层级拆解（构建期） | ≤ 48 节点；每层同一拆分逻辑 |
| `recipe.tree` | 同上，数据驱动 | ≤ 48 节点 |
| `diagram.hierarchy` | 能力／层级地图 | 区分包含、依赖、必要条件 |

### 达成度（kpi）

| form | 何时用 | 容量上限 |
|---|---|---|
| `kit.bullet` | 实际 vs 目标 vs 分档 | 指标 ≤ 6；分档须另有业务定义 |
| `html.kpi` | 少量核心指标的卡片组 | ≤ 5 张卡；每张须有目标线 |

### 机制与流程（diagram）

| form | 何时用 | 容量上限 |
|---|---|---|
| `diagram.mechanism` | 因果链条与反馈回路 | 边须写含义与证据状态；循环标反馈 |
| `kit.swimlane` | 单节点单元格的泳道（构建期） | 单元格仅 1 节点；复杂分支换专门路径 |
| `diagram.swimlane` | 多主体跨阶段的职责与交接 | lane 编码主体、stage 编码阶段 |
| `kit.processFlow` | 3–6 段的线性阶段 | 3–6 段线性；等宽不表示等时长 |
| `diagram.condition` | 条件分支与决策树 | 决策节点与结果分开；概率缺依据就保留分支 |

### 精确查数（table）

| form | 何时用 | 容量上限 |
|---|---|---|
| `html.table` | 读者要逐格核对数值 | 一列一种单位；总计由作者提供 |
| `kit.comparisonTable` | 少量对象的属性对照 | 高度由内容决定，须自行分页 |
| `html.matrix` | 评估矩阵、优先级矩阵、RACI | 权重与评分锚点须透明 |

### 结构化文字（text）与作者实现（custom）

| form | 何时用 | 容量上限 |
|---|---|---|
| `html.text` | 没有共同维度，硬画图会失真 | 无共同维度时保留结构化文字 |
| `svg.custom` | 表内 33 个形式都不适配 | 几何与语义由作者负责，须实际看图 |

## 选型程序

1. 写下页面主张，以及它要求读者看出的**一个**关系（蓝图的 `proves`）。
2. 写下数据的真实身份：观测单位、期间、分母、单位、缺失语义、是否互斥可加。
3. 排除：数据不支持、口径不可比、编码误导、静态不可读、容量超限的方案。
4. **按族把候选召回全**——先看「本技能的表达词汇」里该族有哪些形式，再挑，不要凭记忆只想到最常见的那个。同一族内换形式的代价远小于换族。
5. 在剩余候选中比较：决策任务匹配度、比较精度、重点识别、信息容量、学习成本。
6. 写出主表达。只有存在实质取舍时，才记录一个备选及其胜出条件。
7. 检查标题、图例、标签、尺度、注释和来源是否共同证明同一主张；检查容量是否真的放得下。

## 数据契约

形式对数据有最低要求。字段不满足时先回去补数据或改主张，不要画一张看起来对但语义错的图。

| 族 | 最低需要 | 额外条件 |
|---|---|---|
| comparison | 1 个类目字段 + 1 个数值字段 | 哑铃/坡度需每行两个同量尺数值；瀑布需起点 + 有符号增量 + 能对账的终点 |
| trend | 1 个有序时间字段 + ≥1 数值 | 期间必须连续或显式标出缺口；预测段须与实测分开编码 |
| composition | 部分互斥、可加，且整体有定义 | 仅非负；Mekko 还需一个列规模度量 |
| distribution | 原始观测或已声明的分箱 | 样本量、分箱规则、异常定义必须可写进注释 |
| correlation | 每个观测 ≥2 个数值字段 | 热力图矩阵须为有限数值；缺失格不等于 0，须单独编码 |
| flow | 节点 + 边，且边上有守恒量 | 桑基须无环、守恒，残差与损耗不可隐藏 |
| hierarchy | 父子边 | 每层同一拆分逻辑，不得混用包含/依赖/必要条件 |
| kpi | 实际值 + 目标 + 单位 + 期间 | 分档边界须有业务定义 |
| diagram | 节点 + 带语义标签的边 | 箭头须标作用、交接、包含、前置条件或证据状态 |
| table | 每列一种单位 | 缺失、零值与不适用要能区分 |
| text | 无共同维度 | 有共同维度时应回到能画图的族 |

## 反模式

以下做法在本技能里一律不允许，出现即返工：

- **伪 3D 定量图**、装饰性色条、顶部色条数字卡、无意义图标阵列。
- **气泡按半径映射数值**——必须按面积映射，否则数值被平方放大。
- **双轴制造相关**——两条不同量尺的线并排会让读者读出并不存在的相关。
- **构成图用于不可加或非互斥的数据**——份额图的前提是部分互斥且可加。
- **雷达图**用于维度多且尺度不可比的场合。
- **平滑线伪造连续变化**，或在离散期间上画连续趋势。
- **等宽箭头或等宽节点暗示定量、时长、规模或因果强度**。
- **力导向距离被当作业务距离**。
- **给任意数值套 0–100% 仪表盘**。
- **只报均值而掩盖决定判断的分布**。
- **未说明的截断量尺**；柱与条默认以零为基线，非零折线起点必须显著说明。
- **依赖悬停才能读到的关键信息**——静态读者不能悬停，关键值必须直接显示。
- **用重复图表填页面**——连续三页同一种弱结构要写明它为何仍是最优表达，写不出来就回到材料。
- 用放大主图、拉伸容器或改配色去掩盖证据不足。

## 静态媒介编码底线

- 用共同位置或长度做精确比较；柱、条默认以零为基线。非零折线起点必须显著说明。
- 将实际、预测、缺失、零值、百分比和百分点分开编码，并直接写出单位、期间和基准。
- 多系列遮挡时改小多图、分面或总览加局部，而不是不断加颜色。
- 桑基、瀑布与份额图先验证流量、总量和端点；不隐藏残差、损耗、补充或不可解释部分。
- 颜色只辅助语义，不能成为唯一含义；灰度或投影环境下仍须可解释。
- 容量是硬约束：超过上限时在同一表达内重排、分面或换实现，**不要改成表格再沿用原图型名称**。

## 词汇表之外的表达

33 个形式覆盖不了所有关系。这是**本节唯一的目的**：让读者知道想要的东西本技能有没有，而不是默认"大概就用最像的那个"。

遇到表外关系时只有三种处置，先判断属于哪一种：

| 缺什么 | 能不能用现成形式诚实顶替 | 处置 |
|---|---|---|
| **箱线、小提琴、蜂群、ECDF、分位带** | **不能。** 分布族只有 `recipe.histogram`；中位数、四分位、离群点、尾部形状正是这四个图的全部意义，直方图给不了 | `svg.custom` |
| **小多图、分面** | **不能。** 分面是"同一量尺下的小倍数比较"，不是一张图；`recipe.timeSeries` 的容量里写着"更多分面"，但那是图外的排布技巧，不是形式 | `svg.custom`（各格必须共用同一量尺） |
| **漏斗** | **不能。** `recipe.sankey` 是多对多的量流与损耗，漏斗是单路径的逐级衰减，两者不可互换 | `svg.custom` |
| **甘特、路线图** | **不能。** 需要跨时间的条与依赖；`diagram.condition` 画不了时间轴，`diagram.process` 的等宽节点也不表示时长 | `svg.custom` |
| **地理、位置**——分级设色、比例符号、流向、网格 | **不能。** 没有底图就没有位置编码，这不是图形选择问题 | `svg.custom` |
| **区间、不确定性**——区间点、置信带、森林图、龙卷风图 | **不能。** 点估计加误差棒不是区间编码，它丢掉了区间宽度这唯一的信息 | `svg.custom` |
| **网络、生态、关系**——节点连线、二部图、弦图 | **不能。** 无力导向布局、无弦图实现；且力导向距离不可当作业务距离 | `svg.custom` |
| **矩形树图（treemap）** | **勉强。** 可用 `kit.tree`／`recipe.tree` 顶替层级，但会丢掉面积编码——层级深度还在，规模比例没了 | 顶替须写明损失，否则 `svg.custom` |
| **阶梯线** | **看情况。** 若"台阶"本身就是论证点（阈值触发、跳变），折线会抹掉它；否则可顶替 | `recipe.timeSeries` 或 `svg.custom` |
| **四象限** | **可以。** `recipe.scatter` + 阈值参考线 + 象限标注就是四象限 | `recipe.scatter` |
| **转移矩阵、队列留存图** | **可以。** 二者本质都是矩阵热力，行列表头写清口径即可 | `kit.heatmap`／`recipe.heatmap` |
| **日历热力** | **可以。** 本质同样是矩阵热力，一格一天 | `kit.heatmap`／`recipe.heatmap` |
| **邻接矩阵** | **可以。** 矩阵热力加对称说明即可 | `kit.heatmap`／`recipe.heatmap` |

**本来就有的，不要误当成缺口**：桥接与增量分解用 `kit.waterfall`／`precision.waterfall`（它们的定义就是"从起点经增量到终点的桥接"）；差额标注用 `precision.columns` 的 Δ 入口；排名迁移用 `kit.slope`；两期对比用 `kit.dumbbell`。不要因为名字里没有"桥接"两个字就自己去画。

走 `svg.custom` 时注意两层命名差异：蓝图里写 `"form": "custom"`，`pages.json` 与 HTML 里写 `svg.custom`（由 `verify_blueprint_pages.cjs` 映射）。两者都必须给出 `rationale` / `visual`，说明为何现有形式不适用，并说明几何编码依据——**自定义不等于不受约束**：坐标、量尺、标签、零基线、单位、期间和来源仍须遵守上面的编码底线。静态媒介不能悬停，关键值必须直接标注。

## 将文字翻译成视觉论证

将文本中的主体、动作、条件、依赖、反馈、交付物和反例展开为结构。箭头必须标明作用、交接、包含、前置条件或证据状态；箭头本身不证明因果。

构思时为每页指定一个主视觉，再分配互补说明。可使用不对称版式、嵌入式注释、总览 + 细节或图表 + 机制；不要默认左图右字。若图型重复到第三页或连续三页相同，写明为什么它仍是最优表达；写不出来时，回到材料而不是只换皮肤。
