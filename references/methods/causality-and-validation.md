# 原因识别与验证设计

适用：要声称某动作导致增长、提效、降本或改善体验；只做描述比较时不强造实验。

输入需要结果指标、处理/动作发生时点、对照、分组机制、可能混杂、样本流失、测量定义。先画机制和可竞争解释，区分变化贡献与原因。

1. 先核验指标本身：埋点/口径/重复/漏报是否变化，组成结构是否变化。
2. 随机实验可行时，定义随机单位、主指标、护栏、样本/时长依据、停止条件；避免看见显著就提前停。涉及用户动作或上线必须在授权范围内。
3. 无随机实验时说明对照可比性、前趋势/选择偏差、同期事件、溢出和时滞。前后对比只能给关联线索，不能自动升级因果。
4. 定性机制用反例和过程证据验证；“所有成功案例都有 X”仍受幸存者选择影响。
5. 落地动作定义可观察结果、负责人角色、依赖、测量窗口和决策条件。建议阈值要有依据，未知先写验证任务，不填精确承诺。

输出：识别设计、可支持的效应或描述、未知、复核/停止条件。检查反证是否实际可能推翻原解释；验证指标是否独立于作者期待的结论；局部改善是否转移了成本/风险。
