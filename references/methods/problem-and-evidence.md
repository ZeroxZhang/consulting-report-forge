# 问题分解、证据与反证

适用：目标含糊、素材分散、解释不止一个；不必用于已确认文稿的机械重排。

## 输入

读者要做的决定/理解的问题、可用时间、范围与原始材料。分清现象、目标差距、原因假设、行动四类句子；已知约束不要伪装成假设。

## 执行

1. 写一个能被证据回答的问题，注明对象/期间/比较基准/成功标准。
2. 按同一维度拆子问题，核对覆盖和交互；对于因果，画可能的混杂、反馈和时滞，不强求树状互斥。
3. 按“是否可能改变结论 × 当前不确定性 × 取证可行性”排序，可定性说明，避免无依据精确打分。
4. 对关键解释写预期看到的证据、会推翻它的证据及可替代解释。没有证据时保留 untested，不先写肯定标题。
5. 建来源链：原始文件/页面定位、时点、样本选择、独立性、缺失与冲突；两个网页转述同一报告只算一条来源链。
6. 访谈先按原话片段编码主体/动作/条件，再对照反例；频次需分母与样本范围，不能据便利样本给市场占比。
7. 结果写入 claims；来源核验与假设判定分别更新。反证改变判断时修改总答案，而不是藏到附录。

## 输出与检查

问题/证据矩阵、重要假设状态、可支持主张、未决缺口。检查：有没有遗漏重要反例？范围是否悄悄变化？推荐强度是否超过证据？什么观察会改变当前答案？结构化矩阵可作为内部派生视图，无需所有内容都上页。

参考公开问题解决流程：[McKinsey 七步问题解决](https://www.mckinsey.com/capabilities/strategy-and-corporate-finance/our-insights/how-to-master-the-seven-step-problem-solving-process)。本文的数据合同与工具流程是本技能实现，并非咨询公司的内部 SOP。
