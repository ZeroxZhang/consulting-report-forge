# Slides / PPT 生产交接

本技能负责咨询叙事、证据架构、页面蓝图与审查标准；**Slides 技能和 Slides MCP 负责实际创建、预览、呈现与导出**。不要在本技能目录或普通工作区手写 `.pptx`、独立 HTML 幻灯片或 `project.json`。

## 路由选择

| 用户真正需要的成品 | 使用 Slides 模式 | 选择条件 |
|---|---|---|
| 可在线翻阅、团队评论、精确排版的演示 | `slides-html` | 默认；适合信息密度高、图表/表格/信息图丰富的咨询材料 |
| 可在 PowerPoint 中编辑的原生文件 | `slides-pptx` | 用户明确要求可编辑 `.pptx`；需遵守 Slides 的 XML 语法与验证 |
| 研究型离线阅读稿 | `static-report` | 用户要求自包含HTML/PDF，而非演讲型PPT |

在任何 PPT/幻灯片任务中，先读取 `slides` 技能。Slides 的项目清单、单页文件生命周期和 `present` 交付门禁优先于本技能的任何实现建议。

## 从蓝图到 Slides 的最短可靠路径

1. 研究和核验证据完成后，先填写并校验 `templates/deck-blueprint.json`：
   ```sh
   node scripts/deck_blueprint.cjs /任务/deck-blueprint.json --ready
   ```
2. 将每个 blueprint slide 映射为 Slides outline：`id`、`title`、`subtitle + proves + visual.primary` 的摘要。**不要**在尚无足够证据时先创建空白幻灯片。
3. 以用户指定的模板 ID 或 `style_request` 初始化一个 Slides 项目；一次注册完整大纲。若用户未指定页数，咨询型演示默认控制在 8–12页正文/总页数范围，附录另计。
4. 对每张幻灯片，先把蓝图翻译为：标题、可选副标题、角标、主视觉、支持证据、行动/限制带、来源区、阅读路径。每页只通过 Slides 规定的原生写入路径创作。
5. 完成后在 Slides 预览中逐页执行 [视觉与证据验收](visual-qa.md)，重点查看 `dense` / `balanced` 页是否有视觉空洞、标题与主证据是否匹配、字色对比是否充足。
6. 调用 Slides 的 `present` 作为交付门禁；只有用户明确需要PDF/PPTX时才执行相应导出。

## 页面创作规格

每页都应明确如下内容；不要只向 Slides 提供一段长文：

| 字段 | 必须回答的问题 |
|---|---|
| 标题 | 读者应先接受什么判断？标题的强词有何视觉证据？ |
| 副标题/角标 | 范围、期间、工作流阶段或保密等级是什么？ |
| 主视觉 | 用哪一种关系表达：比较、趋势、构成、机制、取舍、行动？ |
| 支持证据 | 用什么基准、分母、反例、条件或局部展开避免过度解释？ |
| 含义 | 这页如何改变决策、风险判断或下一步行动？ |
| 来源 | 哪些数字或外部判断需要贴近对象的可核查引用？ |
| 版式 | 主辅比例、阅读路径、对齐轨道、留白用途和来源安全区是什么？ |

设计应保持咨询级克制：以深色正文和高对比文字为主；强调色服务于语义；主图优先而非装饰；用共同基线、直接标签和明确条件支撑论点。避免使用模板化三栏卡片、无意义渐变、彩色顶部条、伪3D图、随机图标和把整段文字放进矩形框的“信息图”。

## PPT 专属质检：简化但不放松

不要复制静态报告的脚本验收；在 Slides 预览中完成四个强制动作即可：

1. **缩略图扫读**：标题连读是否是一条论证；是否有节奏失衡或连续重复版式。
2. **100%逐页检查**：核查主证据、支持单元、留白、文字对比、来源、底部安全区和对齐。
3. **最坏页复检**：优先重看信息最密、图表最多、来源最多、以及大留白最多的每类一页。
4. **交付门禁**：所有页面完成、无 `major` / `blocking` 未决项，再调用 Slides `present`；需要可编辑文件时以其PPTX导出结果为准。

复杂研究、重大建议或外部发布材料，安排未参与制作者对标题链、关键数值、最坏页和行动页进行独立复核。该复核可简短，但必须基于实际预览，而不是自动通过信息。
