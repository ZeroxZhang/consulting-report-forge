# 视觉与证据验收

> 工程正确不等于咨询级成品。先看读者是否能理解，再检查图形是否准确。

## 四道最小门禁

不要用冗长的检查表制造“已质检”的错觉。最终只需留下以下四类明确证据；任一道未通过就返工。

| 门禁 | 只检查什么 | 最小操作 | 通过条件 |
|---|---|---|---|
| 蓝图 | 叙事是否完整、每页是否有真实任务 | 运行 blueprint 校验；连读标题与 `adds` | 有明确问题、总判断与有边界的洞见；研究可收束为下一步验证；每页的形式、密度和来源计划完整。`narrative-focus-1` 下另核：弧线走到收束节拍，逐页 `adds` 不重复，核心答案被某一页承担 |
| 缩略图 | 整册节奏、层级、表达适配与多样性 | 连续扫读缩略图/联系表，结合蓝图和形式清单检查变化机会与重复理由 | 在适配范围内尽可能多地使用不同图型与布局；无仅因套模板而遗漏的有效变化；同型分面和连续比较有具体保留依据；不设统一种数配额 |
| 最坏页 | 最高风险视觉和证据问题 | 在逐页检查基础上，每类重点复看一页：最密、最大空白、最复杂图、来源最多、最强结论 | 无微字、遮挡、空洞、误导编码或来源丢失；标题与主证据一致 |
| 交付 | 最终媒介及未决风险 | acceptance audit + 真实审查 | 无 blocking/major 未决项；最终媒介实际打开；审查引用实际预览而非自动结果 |

蓝图校验：`node scripts/deck_blueprint.cjs /任务/deck-blueprint.json --task /任务/task.json --ready`。成稿还须执行 acceptance 档作为交付门禁。

## 整册多样性验收

必须分别核对图表与版式是否落实“尽可能多”，不能用其中一项的丰富掩盖另一项的机械重复。结合蓝图、现有重复诊断与实际整册画面，在现有视觉审查记录中说明发现及处置，不另设种数评分或逐页豁免表。

- **主动变化是否充分：**不同证明任务是否仍被相同图型或阅读结构机械承载？是否存在准确、清晰且适配的其他形式，仅因组件熟悉或制作方便而未采用？有这类机会就回到选型修订，不能只写“已满足内容需求”。
- **重复是否必要：**用具体页码或比较组说明共同量尺、对象对照、内容容量或稳定阅读路径的需要，并核对实际画面。笼统的“内容适配”“保持统一”不足以通过；同口径比较的合理重复可以保留，不要求逐页换图或布局。
- **变化是否真实：**同一图型的不同渲染器、配色或名称合并判断，例如 `kit.waterfall` 与 `precision.waterfall` 均属瀑布图。表格和文字不冒充新增图型；自绘图看实际编码，不凭不同描述算多种。布局按整页阅读区域的实际主辅关系、空间组织与阅读路径判断，图内坐标轴或节点排列的变化、微调比例不自动算新类型，封面与章节页也不能掩盖正文单调。

现有 `R-EXPRESSION-INVENTORY` 按实现 ID（自绘按描述）统计，**不是语义归并后的图型种数**，需在人工审查中按上述口径合并；`L-LAYOUT-INVENTORY` 按声明的阅读结构诊断，仍须核对成稿，不能直接采用按布局 ID 统计的 `distinctLayouts` 作为有效多样性。复用 `R-REPEATED-EXPRESSION`、`R-SAME-EXPRESSION-PANELS`、`L-REPEATED-LAYOUT`、`L-CONSECUTIVE-LAYOUT` 定位重复；未触发提示也不代表已经尽可能多地使用适配形式。

验收应区分：多关系材料应主动展开适配的多种表达与结构；同口径连续比较应保留有阅读价值的一致性；短稿或证据有限的材料不靠增页、虚构数据或无关图示凑种数。数量本身不决定通过，未落实前置要求的机械重复与遗漏机会须修订后复看。

## 成稿的机械排印检查

装配、溢出、字号、图例、绑定这些检查都过了，页面上仍可能印出坏句子——它们都在纯文本层面，只有印出来才看得见：

```sh
node scripts/check_units.cjs /运行目录/deck.html
```

它只判断读得出来的东西：指标 token 已经把值与单位（连同身份括注）印在页面上，正文、标题、主张或限定里再写一遍单位，就会印出 `36.0 亿美元（预测） 亿美元`、`99 笔 笔交易`、`62.4%（估计）%`；把带标签的 HTML 写进会被转义的字段，页面上会直接出现 `<span data-content-key=…>` 这类文字。单位词表不写死在脚本里，直接取自本页的指标元素，换口径不用改脚本。

命中即失败，逐条给出页码与上下文。误报要当缺陷修：把合法写法当成错，作者会为了过检查改坏句子——所以判据里「元素边界」「合法嵌套」「不同单位后缀」都有反例背书（`scripts/test_check_units.cjs`）。

## 整页检查

逐页在实际 HTML/PDF 预览中回答以下问题，并记录具体所见而非泛化评价。

1. 主证据是否首先进入视线，且空间与证明责任匹配？
2. 标题里的差异、链条、条件或取舍是否在图、表或机制中直接可见？
3. 关键差额、阈值、分母、反例和适用条件是否贴近被解释对象？
4. 最大留白和模块内部空白是否服务于分组、强调或阅读节奏？
5. 同层文字基线、共同比较轨道和实际绘图区是否对齐？不要只检查容器边界。
6. 来源与关键限制是否可读且有独立安全区？
7. 色彩、线型和标签是否在灰度或投影环境仍保持可解释性？
8. 该页给全篇增加了什么，是否重复上一页的弱结构？把全册连起来看，重复是否有助比较，变化是否帮助推进论证？重复诊断须结合画面处置，不能为消除提示而换成不合适的图型。
9. 该页的 `density` 合同是否兑现：主展品、支持/背景/行动含义各自承担什么职责？是否少了可从既有证据中提炼的第二层关系？
10. 最大空白是刻意的阅读停顿、比较间隙或来源安全区，还是主图未做够、模块被拉伸、内容集中在上半页后的“空洞”？
11. 这一页只讲一件事吗？把收束句、标题和副标题连起来读——三句是不是同一件事的三种说法，还是各下了一个判断？后者说明页面还没有收束。
12. 读者第一眼落在哪里？那里是不是声明的主展品？若不是，是有意的组织，还是版位比例造成的？

若只能说“元素齐全、没有溢出”，该页尚未通过视觉验收。

## 证据与编码检查

- 对账起点、增减项与终点；核对百分比、百分点、增长率的分母与区间。零或负基数不强行计算常规增长率。瀑布与桥接页另按 [瀑布数据合同](waterfall-bridge.md)：瀑布语义缺少权威输入/对账标记会阻断；`WF-MULTIPLE-AUDIT`（一页两条对账结论）是阻塞项——旧策略保持页面级冻结行为；新策略（`evidence-composition-1`）把作用域下沉到 panel，同页两张独立瀑布各自体检，同一 panel 内重复对账结论仍阻断；`WF-RESIDUAL`（图上有未解释差额）必须亲眼确认差额是独立节点、不是被并进最后一根柱子，蓝图在 `waterfall.residualReason` 写明依据，再编译到 `pages.json`。
- 核对单位、期间、样本、地理范围、统计口径与数据状态；不同口径不能只因外观相似而并列比较。
- 区分事实、估计、预测、目标和建议。预测须说明模型或情景；不把相关性和顺序描述为因果。
- 检查堆积图的总量与份额、小片和零值；必要时用贴近对象的直接标签或引线，不让读者自行反算。
- 审查表格的单位、数值对齐、缺失语义、总计与数据条尺度；表格可作为主动选择，而非降级。
- 检查机制图的主体、责任、交付、条件和箭头语义；流程顺序、等宽节点和版面位置不自动证明因果、时长或规模。

## 视觉返工顺序

遇到大面积无效留白、关系不清、重复弱结构、主次失衡，或整册节奏妨碍理解时，按以下顺序返工：

1. 回到主张和证据，确认是否遗漏可表达的关系；
2. 重选或重组展品与阅读路径；
3. 调整主辅比例、空间、对齐、标注和来源区；
4. 最后处理字号、间距、颜色等局部排印；
5. 重新查看受影响页面的完整 HTML/PDF 预览。

仅在主张确实缺乏支撑时，从下列来源寻找有用证据：同一图的比较基准、异常点、差额/分母、反例、时间维度、机制条件、敏感性、风险边界、下一步行动。若证据充分但绘图区过小，应直接调整尺寸和布局，不必先增加证据单元；保留比较量尺。

不要通过放大背景框、拉高表格行、堆叠文字、添加无关图标或重复结论来伪造“饱满”。允许合理的不对称、经 `sparseReason` 解释的低密度停顿页与为精确查值保留的长表；按阅读任务判断，不因页面被称为正文就否定这些选择。

## 问题分级

| 级别 | 判断标准 | 处理 |
|---|---|---|
| Blocking | 数据/编码误导；核心证据缺失；不可显示、不可打印；关键文字被遮挡 | 修复后再验收，不能交付 |
| Major | 关系表达、证据链、页面重心、层级、色义或用户明确视觉要求显著妨碍理解；或 `dense` / `balanced` 页出现无解释的大面积正文空洞 | 修复后再验收，不能交付 |
| Minor | 不影响理解的小间距、行文或一致性瑕疵 | 记录并在可行时修复 |
| 未验收 | 未完成任务要求的视觉、来源核对或最终媒介导出；按约定只核对提供材料而未做外部核验，不自动等于未验收 | 如实标注，绝不写成 Minor 或 PASS |

## 成品禁忌

不要使用装饰性色条式判断块、顶部色条数字卡、伪 3D 定量图、无来源的精确数字、只靠颜色区分状态、截断且未说明的量尺，或需要悬停才能读到的关键证据。不要以“简洁”“AI 生成”“自动检查通过”作为删除必要证据或跳过人眼验收的理由。

工程检查覆盖声明的内容绑定和语义，不能穷尽所有未登记文字。还要检查图形几何与原始数值是否一致、标题是否有未被主张支持的因果词。局部修订见 [审查复用](review-reuse.md)，继承只覆盖未变化页的既有证据，不继承本次全局判断。
